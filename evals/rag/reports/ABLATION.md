# dense vs hybrid：2026-07-28，修复 sparse 权重之后

## 先说作废的部分

**此前所有 hybrid 数字均无效**，包括本文件前两版记录的两组。原因不是测得不准，
而是被测的东西不存在：BGE-M3 的词法投影头 `sparse_linear.pt` 从未被加载，
每次运行使用的是一个**随机初始化**的投影矩阵。详见 `SPARSE-DIAGNOSIS.md`。

修复后重测，结论与作废的那些相反。

## 结果

两轮独立运行，同一份语料（10 篇）与 gold set（38 题，digest `a26070043b0ffde1`）。

| 指标 | dense run1 | dense run2 | hybrid run1 | hybrid run2 |
|---|---|---|---|---|
| recall@1 | 0.9474 | 0.9474 | **1.0000** | **1.0000** |
| recall@3 | 0.9737 | 0.9737 | **1.0000** | **1.0000** |
| MRR | 0.9605 | 0.9605 | **1.0000** | **1.0000** |
| 检索延迟 | 41 ms | 46 ms | 27 892 ms | 7 219 ms |

**两个 arm 的质量指标都逐位复现。** dense 一直是稳定的，它在这里的作用是对照组：
它证明评测装置（语料、切分、索引、gold、打分）本身确定，两轮之间没有别的东西在变。
hybrid 从「每轮都不同」变成「两轮完全相同」，这是修复生效的直接证据。

## hybrid 优于 dense

38 题全部命中且全部排第一。dense 漏掉 2 题的 rank-1（recall@1 0.947），
其中 1 题连 top-3 都没进（recall@3 0.974）。

这是**第一次可以真正做这个比较**——此前每一次比较都有一侧是随机量。

需要克制的地方：38 题上的 1.000 不是「hybrid 完美」，而是「这个 gold set 不够难，
已经区分不出 hybrid 内部的好坏了」。它能区分 hybrid 与 dense，不能再往上区分。
下一步若要继续测 hybrid，需要更难的问题，而不是更多同类问题。

## 延迟：现象仍在，原因未分离

hybrid 延迟在 7.2 秒到 27.9 秒之间，比 dense 高两到三个数量级，且两轮之间差 3.9 倍。

**本文不给这个现象一个原因。** `retrieval_latency_ms` 把稀疏编码与向量检索合并计时，
所以现有数据分不开至少三种可能：BGE-M3 稀疏编码在本机 CPU/MPS 上本就昂贵、
Qdrant 稀疏检索本身慢、或还有第三个未发现的问题。

不写结论是刻意的。本文件上一版就是把整个延迟数量级归因给一个刚找到的 bug
（融合前截断），而那个归因后来被证明不完整——找到一个能解释现象的原因，
不等于找到了全部原因。

值得记下的是：**延迟仍在波动，质量已经不波动了。** 这两件事此前是绑在一起的
（随机投影同时破坏两者），现在分开了，说明延迟波动不再意味着向量在变。

下一步是把编码与检索分开计时。在那之前，「hybrid 慢」只是一个观测。

## 更正两处旧论断

1. **「hybrid 劣于 dense」**（07-27 版）——建立在随机投影的单次采样上。作废。
   修复后结论相反。

2. **「30.3 秒由融合前截断造成」**——截断确实是一个真 bug，修它是对的；但把整个
   数量级归因给它是过早收敛。修复就位后 33.5 秒重新出现过，说明底下还压着别的。

## 三臂消融（WP05-08）的状态

`scripts/run_rag_eval.py` 已支持第三臂 `hybrid-rerank`，本轮**未跑**：
bge-reranker-v2-m3 的权重（约 2.3 GB）不在本机，两轮运行均设 `HF_HUB_OFFLINE=1`，
脚本按设计跳过该臂并打印原因，不会产出缺一条臂的三臂报告。

现在跑它是有意义的——基线已经可复现。但 hybrid 在这个 gold set 上已经打满 1.000，
**rerank delta 在这里必然为 0**，测不出任何东西。要测 rerank，先要更难的 gold set。

## 复现

```bash
docker start aw-qdrant
AGENT_WORKBENCH_TEST_QDRANT_URL=http://localhost:6333 \
  uv run --extra embedding python scripts/run_rag_eval.py
```

需要 `sparse_linear.pt` 在 HuggingFace 缓存中，否则加载器拒绝启动并给出取回命令
（这是修复的一部分：下载只解决一台机器，拒绝启动解决所有机器）。

CI 不跑：没有嵌入运行时，用确定性 embedder 跑出的报告是在测一个哈希函数。

原始输出：`dense.json`、`hybrid.json`（run2），`hybrid-run1.json`（run1，用于比对）。
