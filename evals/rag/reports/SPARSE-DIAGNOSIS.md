# 为什么 hybrid 输给 dense：查到一半的诊断

状态：**未定论**。这里记录的是实测现象和被排除的解释，不是结论。

## 现象：sparse 编码跨进程不可复现

同一个查询，三次独立运行，编出的词项数不同：

| 查询 | 运行 A | 运行 B | 运行 C |
|---|---|---|---|
| `RRF` | 0 | 2 | 0 |
| `reciprocal rank fusion` | — | 0 | 1 |
| `AWB-4471` | 4 | — | 3 |
| `Qrdant` | 0 | — | 2 |

**每次运行内部完全自洽**：同进程内连编三次结果相同，批量路径与单条路径也一致。
所以不是随机性，是跨进程状态差异。

## sparse 单独检索：即使编出词项，排序也不对

运行 A 里绕开融合、只用 sparse 查询：

```
'AWB-4471'                                    4 词项 -> [quoted-guarantee, events, error-codes]
'never be reassigned, reordered, or skipped' 10 词项 -> [quoted-guarantee, outbox, authorization]  ✓
'Qrdant' / 'RRF' / 'recieved chunk batch'     0 词项 -> []
```

`AWB-4471` 编出了词项，却把唯一含该错误码的文档排在第 3。

## 已排除的解释

- **不是「短查询固有编不出词项」**：`Qrdant` 在运行 C 编出 2 个词项。
- **不是批量路径 bug**：批量与单条一致。
- **不是随机性**：同进程内可完全复现。
- **不是融合权重**：sparse 单独检索本身就排不对。

## float16 / MPS 假设：已实测排除

先前的猜测是 float16 与 MPS 后端的舍入差异，让阈值边缘的词项在不同进程落到两侧。

**固定 `device="cpu"`、`use_fp16=False`（纯 float32、同一 torch 2.13.0）后，两个独立
进程仍然不同**，而且差异更大：

| 查询 | 进程 1 | 进程 2 |
|---|---|---|
| `RRF` | 2 项 `(627, 54612)` | 1 项 `(54612,)` |
| `Qrdant` | 3 项 `(42, 2396, 58349)` | 1 项 `(58349,)` |
| `recieved chunk batch` | 7 项 `(13, 92, 206, …)` | 1 项 `(24862,)` |
| `AWB-4471` | 0 项 | 0 项 |

假设不成立：精度与设备都不是变量。

## 新线索：疑似权重未完整加载

进程 2 里几乎每条查询都塌成 **1 个词项**，且 `recieved chunk batch` 的那个索引
（24862）**不在**进程 1 的 7 个之内。这不像舍入误差在阈值附近抖动——抖动会让边缘词项
增减，不会让结果整体塌缩并换成一个全新的词。

更像**两次加载得到了不同的模型状态**。旁证：加载时打印
`Loading weights: 0/391 → 391/391`，速度 80000+ it/s，快得不真实。

### 下一步的具体检查项

1. 比较两次加载后 sparse 线性头（`sparse_linear`）的权重张量是否逐值相同；
2. 确认 FlagEmbedding 是否真的加载了 `sparse_linear.pt`，还是回退到随机初始化——
   BGE-M3 的稀疏头是**独立于主干**的一组权重，主干加载成功不代表它也加载了；
3. 若确为随机初始化，则此前所有 sparse 数字（含 #46 的负结果）全部作废。

**在这三项完成之前，任何关于「sparse 有没有用」的结论都不成立，包括 #46 那个
hybrid 劣于 dense 的负结果。**

## 一条已合并的测试是不稳定的

`test_the_real_model_weights_real_terms` 断言 `reciprocal rank fusion` 的词项数
`> 0`，而实测该查询在不同运行里得到 0 和 1。**它一直在通过，是运气**。

没有改动它：在编码稳定之前，把它改成任何具体期望值都是把噪声固化成契约。这条记录
本身就是它的说明。

## 这一轮里没有做的事

**没有把任何单次观察写成测试。** 第一版诊断（"短查询固有地编出零词项"）就是从一次
运行读出的性质，写测试时立刻被下一次运行推翻——那两条测试已撤回。
