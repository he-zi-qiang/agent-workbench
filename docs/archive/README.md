# 历史归档

这个目录放**已经完成使命的过程文档**：某一时点的审计快照，以及已经全部落地的
工作包实施计划。

**归档不是作废。** 这些文件没有被删，因为它们记录的是*当时看到了什么、为什么那样
决定*——那部分内容不会因为代码往前走而变假。一个只保留最终状态的仓库，读起来像是
每个决定都一次做对的。

**归档的含义是：它不再描述当前代码，因此不该在"这个项目现在是什么样"的问题上被引用。**
判断当前能力，看这三份：

| 问题 | 去哪儿 |
|---|---|
| 现在做成了什么 | [实施状态](../status.md) |
| 现在**没有**做什么，为什么 | [已知缺口](../known-gaps.md) |
| 现在的约束与契约 | [架构基线](../architecture-baseline.md)、[配置契约](../configuration.md) |

## 归档判据

一份文档在满足以下任一条时移进来：

- **它的标题里有日期**，且那个日期描述的是一次已经结束的核验；
- **它是某个工作包的实施计划，而该工作包的每个阶段都已落地**（落地证据在
  [实施状态](../status.md)），于是它从"要做什么"变成了"当时打算怎么做"；
- **它的勾选项已经不再随代码更新**，继续摆在索引里会让读者拿它当现状核对表。

反过来，只要一份文档还在被用来判断"现在能不能做某件事"，它就留在 `docs/` 里，
哪怕内容已经很旧——旧的现状文档要**修**，不能靠归档回避。
