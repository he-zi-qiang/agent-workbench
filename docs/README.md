# 文档地图

这个目录区分**已经实现的工程事实**与**尚待实现的目标设计**。架构或计划里出现某项能力，
不代表仓库已经具备它——判断当前完成度，只认[实施状态](./status.md)、
[已知缺口](./known-gaps.md)和可复现的测试证据。

**门禁数字不在本页。** 它们只在 [十分钟版本的门禁与规模一节](./HIGHLIGHTS.md#2-门禁与规模)
维护一份，其余文档一律链接过去、不复述具体数值。数字散在多处的结果是改一处漏三处，
而"过时的数字"读起来和"当前的数字"一模一样。

第一次读这个项目，从[十分钟版本](./HIGHLIGHTS.md)开始：它不引入任何新主张，
每条陈述都能在下列文档或代码里找到出处。

## 三、治理与证据

**判断"现在是什么样"，看这三份。**

| 文档 | 回答什么 |
|---|---|
| [实施状态](./status.md) | **做成了什么**——逐 PR 累积，含每次增量当时的门禁数字与证据链 |
| [已知缺口](./known-gaps.md) | **没做什么，为什么，做完算什么样**——按"拒绝／未接线／未实现／已知代价／口径不实"五类，每条附仓库位置 |
| [十分钟版本](./HIGHLIGHTS.md) | 上面两份的浓缩，外加**门禁数字的事实来源**：一条真实事件流、四个技术判断 |

"口径不实"单独成一类，是因为它和其余四类危害不同：未实现的东西读者看得见，
**声称已实现的未实现的东西，读者看不见**——它把一个缺口伪装成一个能力。

## 维护规则

1. **门禁数字只在 [十分钟版本 §2](./HIGHLIGHTS.md#2-门禁与规模) 维护一份**，其余文档链接它。
2. **一份文档只在顶部锚一次基线**，正文各节不再重复钉 commit——同一份文档钉两处，
   刷新时改一处漏一处就自相矛盾。写着"本节不钉 commit"的章节里尤其不能钉。
3. **hash 记的是"测量时那棵树"，不是"当前基线"**。措辞要能体现这一点，否则它读起来
   像一句需要读者自己去核的旧话。
4. **一份文档不再随代码更新时，移进 [archive/](./archive/) 并在那里登记理由**。
   只挪文件不写理由，等于把它从"过期"降级成"失踪"。
5. 数字过时是**持续现象而不是一次性缺陷**（见[已知缺口](./known-gaps.md) E-05）。
   真正的出路是 E-04 的 evidence manifest——让"过时"在 CI 里失败，而不是靠人记得来改。
