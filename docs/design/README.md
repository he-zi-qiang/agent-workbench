# 设计稿存档

这个目录放的是**尚未落地的视觉稿**，不是实现。`docs/frontend-design.md` 描述的是
`web/` 里已经存在的东西；这里描述的是有人提议但代码还没跟上的东西。两者冲突时，
以代码和 `frontend-design.md` 为准——存档进来是为了让重构有个可引用的对象，不是
为了给它先发的权威。

## agent-workbench-refactor-2026-08-18.dc.html

2026-08-18 收到的整体重构稿，Claude design-doc canvas 格式：单文件 HTML，靠
`<x-dc>` / `<sc-for>` 模板和一个 `class Component extends DCLogic` 渲染 1440 × 900
的七个屏——工作台·对话、工作台·任务、Code、知识库、评测、计算机控制、运行状态。

**它不能直接跑。** 头部 `<script src="./support.js">` 指向 design-doc 的运行时，那个
文件没有随稿子一起给过来，所以浏览器直接打开是一片空白。别浪费时间去点它。要读
就读源码：样式、布局、文案全部内联在标签上，`data-dc-script` 那段里是数据与派生
逻辑（`NAV` / `SCREENS` / `TITLES` / `BEAD_TONES` 与 `renderVals()`）。

### 相对现状的增量

导航基本是 `AppShell.tsx` 现有那套的翻版（工作台 / Code / 知识库 / 评测 / 状态，
分隔线同样由 `primary` 推导），真正的新东西有三处：

- **新增「计算机控制」一屏**，`primary: false`，与知识库/评测同级。稿子里它把自己
  和其它工具区分开的方式是讲作用域：别的工具作用在本进程的工作区、数据库、沙箱
  容器上，这一个作用在跑 Worker 的那台机器本身。
- **一条青色语义 `#3f6472`**（浅色态 `#eef3f5` / `#dbe4e7`），承载引用、授权与
  发布边界——不表达好坏，只表达"这句话的依据在哪、这个动作被谁允许"。
- **工具授权四件套的珠串**（提议 → 授权 → 开始 → 完成，被拒时第二颗变「被拒」），
  把 Task 时间线上现在只是一行文字的授权事实画成四段。

### 保留的部分

暖中性画布 `#f2f0eb`、深色 rail `#1b1917`、橙色唯一动作色 `#d97757`，以及
success `#2f7a54` / warning `#9a6724` / danger `#b44f4b` 三档状态色，与现有 token
一致。稿子自称「补上真正的深色 rail」。

### 初读时看错的两处

写这份说明的第一版时判断错了两件事，留在这里，因为错的方向是同一个——低估了稿子
背后已经存在的东西：

1. **说「后端目前没有对应能力，这一屏整个是 Planned」，是错的。** `computer_mcp/`
   连同 `gate.py`、`ports/screen.py`、`adapters/screen/darwin.py`、
   `domain/computer.py` 都在，ADR-070 也在。稿子上那四道门禁检查、tier 推导规则、
   拒绝文案，逐条都能在代码里对上，拒绝文案甚至是 `refusal()` 的逐字输出。
2. **说青色「等于加了第五档，加不加要先定」，也不准确。** `--aw-info` 本来就是
   `#486b7a` 这支青灰，色相几乎一样。它不是第五档，是第四档换了个有断言的名字。

顺带更正：`CLAUDE.md` 说 ADR 是 0012–0062，实际到 0070。
