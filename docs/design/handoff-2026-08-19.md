# 交接：Agent Workbench UI 重构

## 这是什么

七屏重构稿：全局外壳、对话、任务、编码、知识库、评测、系统，外加按 ADR-070 新增的计算机控制屏。

**保真度：高保真。** 颜色、字号、间距、圆角都是最终值，可以逐像素照做。

**但这些 HTML 不是要合并的代码。** 它是设计参照，用来说明界面该长什么样、该说什么话。
目标代码库已经存在（`web/` 下的 React + TypeScript + 手写 CSS），所以实现方式是
**改那些已有文件**，不是新起一套。下面每一屏都写了改哪个文件。

## 起点：先读这三份

1. `docs/adr/0066`–`0070` —— 这五份 ADR 是本稿大部分决定的来源，稿子只是把它们画出来。
2. `web/src/features/work/lifecycle.ts` —— 任务时间线的状态机权威。README 里的节点图是旧的，不要照它画。
3. `web/src/components/media.ts` —— 文件能不能预览、预览要花多少代价，全部在 `previewKind` 与 `checkCost` 里。

## 本稿改动了什么（按屏）

### 编码屏：产出卡

改 `FileCard.tsx` 的两处显示，逻辑本身不动：

- **动词只有四个**：`写入` / `覆盖` / `修改` / `运行时写出`。不要加「新建」——事件窗口有起点，
  写在窗口开始之前的文件和从没存在过的文件分不出来，`metaOf` 的注释写明了这一点。
- **meta 拼法**：`动词 · 大小 · 类型标签`，后面按条件追加 `点开可以运行`（`cost === "one-action"`）
  与 `第 N 轮又改过，预览的是最新内容`（`supersededByTurn !== null`）。
- **`就地预览` 折叠**对 `text` / `image` / `html` 三类展开，其余不给折叠：
  - 文本：`<pre>`，高度封顶 `--aw-preview-height-inline`
  - HTML：沙箱 iframe，按 `--aw-preview-logical-width: 1024` 排版后整体缩到容器宽度。
    **缩放系数必须在 JS 里算**——`app.css:2861` 的注释说明了原因：CSS 里没有长度除长度
    得到无量纲数的写法。稿子用 ResizeObserver 量容器宽度写 `scale(width / 1024)`，
    真实实现应沿用 `.aw-preview-frame[data-scale="fit"]` 那条路（React 算好写进 style）。
  - 图片：小于 4 MB 自动展开（`AUTO_PREVIEW_WRITTEN_MAX_BYTES`）
- **两句不同的「看不了」**必须分开说：`unchecked`（.xlsx 一类）说「这个控制台没有能显示它的
  查看器」；`elsewhere`（运行产出里的 .py，`canRun: false`）说「这个文件也能跑，在工作区里
  打开它就有运行按钮」。
- **`disabled` 只对应「已不在工作区」**（`entry === undefined`）。`unchecked` 的卡片照样可点，
  它仍然路由到右侧面板。

### 对话屏：引用（ADR-067）

- 原文**不随答案一起发布**。不要渲染 `Citation.quote`——那个字段在全仓生产代码里从未被赋值。
- 每次点开是一次新读取：`GET /v1/chat/sessions/{id}/turns/{turn_id}/citations/{chunk_id}`，
  按 (会话 · 轮次 · chunk) 三段寻址，授权与 revision **当场重做**，不重放存下来的结论。
  所以一条昨天的引用今天可以正确地 404，这是要保住的行为。
- 三种状态都要画：已读到 / 未读（`点开取原文`）/ 读不到。
- 失败只说一句「读不到这段原文了」，不区分权限收回、revision 变了、点不在索引里。
- 没绑 turn id 的轮次（刷新后的历史）chip `disabled`，因为那次点击必然 404 而原因与权限无关。
- 段落 `staleTime: Infinity`，不重新轮询。

### 任务屏：时间线

- 六个状态全部要有：`done` / `active` / `failed` / `waiting` / `pending` / `skipped`。
  `skipped` 最容易漏——终态任务上没跑过的阶段不是卡住了，是图路过了它。
- 分段按 `lifecycle.ts` 的 `V1_STAGES` / `V2_STAGES`，v1 六段 v2 四段，从 `TaskSubmitted`
  的 `graph_version` 判断用哪套。**不要照 README 的节点图画。**
- `ToolFailed` 不把阶段标红：策略拒一次工具、任务照样成功是常态。
- 工具执行步骤显示「已经跑了 N 秒」（ADR-068），**不画百分比**——已耗时不是完成度。

### 默认运行态

本稿按 `export_requires_approval = false` 复现：任务详情页没有审批区，编码调用不向人要授权。
闸门代码在 main 上仍然存在（`WorkPage.tsx` 的 `<ApprovalSection>`），只是默认配置下不出现。
如果要同时支持两种配置，审批区按条件挂载，不要做成常驻的空区域。

## 没做的

- ADR-069（脚本自己报告在跑）：容器内 stdout 的 live 帧还没画。
- 文档标题需要一个按 `document_id` 取名的读接口，当前只有 id 与 version 可信。
- 历史记录里的引用标记（known-gaps F-16）：`GET /messages` 只回 role + text。
