# ADR-0117：模型没在跑的时候，人可以操作那个浏览器；右栏的文件可以删和改名；一台部署只画三档

- 状态：Accepted
- 日期：2026-09-13
- 关联：ADR-0113（受控浏览器——§4「不做人对浏览器的直接操作」被本 ADR **按它自己给出的条件**翻案：
  它要的是「两个操作者之间的仲裁」，本 ADR 给出一条）、ADR-0116（放手做与删改名——本 ADR 把删改名
  给到人手里，并对四档做取舍）、ADR-095（帧的轮询形状——本 ADR 只在有焦点时把节奏加快）

## 1. 背景

ADR-0116 落地、栈重建之后，用户早上发了一轮「验证马里奥」，然后说了三句话：

> 浏览器还是不能操作，预览就是大部分情况就可以在浏览器中预览，但是现在不可以，
> 文件夹中的文件也不可以删除，四种权限有交叉请取舍

逐条查实：

1. **「浏览器还是不能操作」**：右栏「浏览器」那一张是 ADR-0113 §3.6 的只读回流——一张一秒一次
   的截图，面板底下写着「只读：这里看得到模型在做什么，但点不动它」。用户参照的是 Claude Code
   desktop 的 Browser 面板：那是一个人也能点、也能打字的真浏览器。
2. **「预览……现在不可以」**：在测试标签页里复现到一件事：`aw.code.panel.v2` 记着一次收起，右栏
   整个不渲染，而把它叫回来的那颗「工作区 N」开关**只在会话产出过文件时才画**——一段只读了目录、
   什么也没写的项目会话，收起之后没有任何看得见的路能回去（唯一的路在 ⋮ 菜单里）。清掉那个键、
   刷新，再点 `mario.html`，沙箱预览正常渲染出游戏。所以「预览不可以」是「预览栏不见了」。
3. **「文件夹中的文件也不可以删除」**：`api/client.ts` 里 `deleteProjectFile` 从来存在，**没有任何
   组件调用它**；改名连接口都没有。ADR-0116 给了模型 `project_delete` / `project_move`，人自己在
   右栏里打开一个文件之后一件也做不了。
4. **「四种权限有交叉」**：四档各对应 Claude Code 的 plan / default / acceptEdits / bypass，各有各的
   问题；但读者看到的是四句都以「这一轮……」开头、后两句都说「只有……例外」的提示——「自动改动」
   与「放手做」在字面上分不开。

## 2. 决定

**四件事。**

### 2.1 人可以操作那个浏览器，条件是没有回合在跑

- **浏览器端**（`apps/browser_mcp/contract.py`、`session.py`）：`browser_interact` 的 `click` 多一种
  写法——`x`、`y`（视口 CSS 像素），没有 ref 时按点点击。模型照旧用 ref：一个把页面读成树的东西，
  点不是它的语言；人看的是像素。
- **控制面**（新模块 `apps/api/routes/browser_input.py`，`POST /v1/browser/input`）：把人的一组
  手势（点击 / 按键 / 输入 / 滚动，一次最多 10 个）作为**一次** `browser_interact` 送进去。三道拒绝：
  没有 `mcp:browser` scope 是 403（人驱动这个浏览器，持的是模型持的同一把 scope）；浏览器不在是 503
  （与帧那条路由同一个码）；**有编码回合在跑是 409**——这就是 ADR-0113 §4 要的仲裁，而且是全部：
  模型在跑的那一轮里页面归模型，其余时候归人。不排队、不穿插——模型下一次 snapshot 描述的必须是
  它自己上一步之后的页面。
- **只有 `browser_interact`。** 不转发 `browser_open`（人不替模型决定它在看哪一页），不转发
  `browser_eval`（在模型的页面里打 JavaScript 是控制台，不是面板）。那一次调用长在 `BrowserSlot.
  interact` 上，路由模块本身不含任何工具名；`tests/architecture/test_browser_forward_is_read_only.py`
  多三条：输入模块不计算任何工具名、只有它带请求体、帧模块仍然是一次 GET。
- **面板**（`BrowserFrame.tsx`）：画面变成一个可聚焦的 `role="application"`；点一下把画面像素换算成
  视口像素送点击，焦点在里面时方向键、回车、空格、字母送按键，滚轮送滚动；Ctrl / Meta / Alt 组合
  不送（那是读者自己浏览器的快捷键）。有焦点时取帧 250 ms 一张，否则照旧一秒一张（ADR-095 的形状
  不动，只是节奏随焦点变）。409 那句话画在画面下面，而不是让点击悄悄丢掉。
- **不是一次 tool call**：没有信封、没有策略回合、没有事件。人在操作一个这个进程替他跑的浏览器，
  和他在旁边那个沙箱预览里按方向键是同一件事；审计是路由的访问日志加上模型下一次 snapshot 看到的
  页面。

### 2.2 右栏里打开的项目文件可以删、可以改名

`PreviewPanel` 页眉对项目文件给「重命名」「删除」（会话产出照旧只给「下载」）。删除先 `window.confirm`
（和删除会话那一处同一个理由）；改名 `window.prompt` 新路径。两者走 `DELETE /v1/projects/{id}/file`
与新增的 `POST /v1/projects/{id}/file/move`——后者调的正是 ADR-0116 给 `project_move` 加的那个
`ProjectFileStore.move`，所以拒绝的口径一样：目录不删，目标不覆盖（409），源不在（404）。成功之后
目录树按项目键失效重取，打开的文件跟着关掉或换成新路径。

### 2.3 收起的右栏叫得回来

那颗带 `aria-expanded` 的开关对**有目录的会话也画**：有产出文件时叫「工作区 N」，否则叫「文件夹」，
点开落到目录那一张。

### 2.4 一台部署只画三档

`offeredPermissions`：第三档永远是「这台部署允许的最自动的那一档」。命令跑进 runner 容器的部署上
（`code.unattended` 为 available）画「放手做」，不画「自动改动」；原生路径上反过来。三档的提示改成
说清**问什么**：「每一次写入、每一条命令都先问你」／「写入不问，命令先问你」／「写入和命令都不问，
只有会毁掉工作的几种命令例外」。四档的语义都还在（信封那两半一个字没动），取舍的是**同时画出来
的数量**——正是「自动改动」在容器那条路上产生了十张审批卡。

**补记（2026-09-13，第八十九批）：按下的那一颗一定是画出来的三颗之一。** 本节取舍了画几颗，缺省却没动：
`permission` 仍从 `act` 起步，而提供「放手做」的部署上 `act` 不画。在 Compose 栈上打开一段会话，三颗的
`aria-pressed` 全是 false；不点任何一颗就发出去的一轮，是一档屏幕上不存在的「自动改动」——写入不问、命令
先问，也就是本节取舍掉的那十张审批卡（用户此前的原话：「已经有自动权限还是来询问我的同意」）。
`drawnPermission`：「去做」这个槽位跟着第三档走，`act` 在不画它的部署上发成 `auto`，`auto` 在不画它的部署上
发成 `act`；按下的那一颗、随请求发出去的那一档、「按这个计划执行」和预览报错后的自动验证用的都是这一个值。
**代价**：这台部署上的缺省从「命令先问」变成「命令不问」（会毁掉工作的几种命令形状照旧先问，ADR-0116）。
Claude Code 的缺省是 default——要问；这里沿用的是本仓库自己的缺省理由（`CodePage.tsx` 那一行：「绝大多数
请求就是要它去做」），而在这台部署上，「去做」画出来就是「放手做」。要让每台部署的缺省都是「改前问我」，
改的是 `useState<CodePermission>("act")` 那一行，`drawnPermission` 不用动。

## 3. 为什么是这些做法

- **仲裁规则为什么是「有没有回合在跑」而不是更细的**：一个页面同时只有一个操作者，这是唯一能让
  模型的 snapshot 与它上一步保持因果的规则；按会话细分要先回答「哪个会话的模型在看这个浏览器」，
  而浏览器进程只有一个上下文（ADR-0113 §4 第二条）。粗的规则是对的规则。
- **为什么不把沙箱预览当成答案**：沙箱预览能跑的是**文件**，而人要点的是**模型正在看的那一页**——
  它可能是模型刚 `browser_open` 的一个网址，沙箱里根本没有。两样都留：文件用沙箱（人的浏览器，
  零延迟），模型的页面用回流（250 ms 一帧，能点能按）。
- **为什么删改名走 `window.confirm` / `window.prompt`**：仓库里删除会话已经这么做，理由写在那里；
  一个自己的对话框是第二套确认语言。
- **为什么是取舍而不是改名四档都留**：用户的原话是「请取舍」。改名（「只问命令」「都不问」）能消
  字面上的交叉，消不掉「同一条路上两档只差一句『例外』」的选择成本；而每台部署上第三档只有一个
  真正合理的答案。

## 4. 代价与已知缺口

- **250 ms 一帧的轮询不是 60 fps**（F-43）。能点按钮、能按方向键走几步、能看结果；打一局动作
  游戏要去沙箱预览（文件）或者自己开浏览器。推流（WebSocket / WebRTC）是另一条 ADR。
- **仲裁按进程而不是按会话**：任何一段会话有回合在跑，人都点不了——多会话并发时会被无关的回合挡住。
- 面板换算坐标用的是 `naturalWidth / clientWidth`，截屏与视口等比时成立（`VIEWPORT` 1280×800，
  `deviceScaleFactor` 1）；改了缩放要同时改这里。
- `ADR-0113 §4` 第一条不再成立；那一节在原 ADR 里保留原文并加一行指向这里。
