# ADR-090：一个坐标带着它是在哪块屏上量的

- 决策点：[ADR-076](./0076-a-window-nobody-approved-is-not-in-the-picture.md) §4 在对照
  Claude Desktop 时发现「坐标参照系没钉」，认定它不是文档缺口而是**活着的 bug**，
  然后明确不在那一轮修（「这一轮范围已经够大」），记成 known-gap **F-22**。这一轮修它。
  两个空间怎么合一、换算放哪一层、以及一个没说清自己在哪块屏上量的坐标该被怎么对待
- 状态：**接受**。端口下面一律是**全局点**；`Display` 带上自己的原点；换算是纯算术，
  放进 `domain/computer.py`；坐标**带着 display_id** 走。附带一条比换算本身更要紧的
  收窄：**机器上不止一块屏时，省略 display_id 是拒绝，不是「当作主屏」**。
  **关闭 F-22**
- 日期：2026-08-28
- 影响：`domain/computer.py` 新增 `DisplayFrame` 与 `off_frame`（模块从「三个问题」
  变成四个）；`ports/screen.py` 的 `Display` 新增 `origin_x`／`origin_y`（**无默认值**）
  与 `frame()`，模块注释改写参照系那一段；`adapters/screen/darwin.py` 的 `_display`
  读 `CGDisplayBounds`；`adapters/memory/screen.py` 新增 `SECOND_DISPLAY`；
  `apps/computer_mcp/gate.py` 新增 `_display_for`／`_landing`；`left_click` 与 `scroll`
  两个工具的 schema 新增可选 `display_id`，截图结果改为报出该回填哪个 id；
  `web/src/features/computer/ComputerPage.tsx` 补上这一步。**六个工具还是六个**
- 依赖：[ADR-070](./0070-a-permission-is-about-a-window-not-an-application.md)（§3.2 把
  **单位**钉死成点——本 ADR 钉的是**参照系**，是同一件事没做完的那一半）、
  [ADR-076](./0076-a-window-nobody-approved-is-not-in-the-picture.md) §4（记下这条并
  明确不修；本 ADR 兑现它）

## 1. 一个不会失败的错误

`capture` 返回**那一块显示器**的点尺寸，模型照着那张图量坐标。`click` 把坐标交给
`CGEventCreateMouseEvent`，而 CGEvent 发的是**全局坐标空间**的事件——横跨所有显示器，
只有主屏的左上角是 (0, 0)。

一块屏时这两个空间**是同一个空间**。换算是恒等函数，写不写都对。

接上第二块屏，照着 `screenshot(display_id=2)` 量出来的 `(300, 200)` 就是主屏上的
`(300, 200)`。**没有任何东西会报错**：事件构造成功，投递成功，工具返回
`Clicked in Notes.`，点击落在别人的窗口上。

这类错误比崩溃难对付，因为它没有失败面：唯一的观测者是坐在那台机器前、看见光标
跳到另一块屏上的人，而 Worker 那一侧读到的一切都正常。ADR-076 当时的原话是
「我们把**单位**钉死了，**参照系没钉**」，说得准确——这不是一份文档少写一句，
是代码里同时存在两个互不知情的答案。

## 2. 换算放在哪一层，是这条能不能被测的全部

`adapters/screen/darwin.py` 是这个仓库里唯一测不了的模块：它要 pyobjc，pyobjc 在
macOS-only 的 extra 后面，CI 不装（ADR-070）。而 F-22 自己写的判据是

> 两块显示器上各点一次，落点都对得上。**今天这台机器只有一块屏，所以这条在这台
> 机器上验不了**，需要外接一块才能测。

那句话对**端到端**成立，对**算术**不成立。所以换算被拆成两半：

- **「这块屏的左上角在全局空间的哪里」**——只有平台答得上，放 `darwin.py`，
  一行 `CGDisplayBounds`；
- **「已知原点，把这块屏的点换算成全局点，以及这个点在不在这块屏上」**——纯算术，
  放 `domain/computer.py` 的 `DisplayFrame`。

于是 F-22 的判据里那句「验不了」，只剩下第一半还验不了（谁也没法在一块屏的机器上
证明 `CGDisplayBounds` 报得对），第二半——也就是**会算错的那一半**——由
`adapters/memory/screen.py` 里的 `SECOND_DISPLAY` 完整覆盖。

那个假显示器的两个偏移量是 `origin_x=1470`、`origin_y=-124`，选成这样是有意的：
**互不相等**（换算把 x 和 y 弄反会失败），**其中一个为负**（一块摆得更高的外接屏
是常见摆法，不是刁钻用例；丢掉符号会失败），**都不是对方尺寸的倍数**（碰巧对称
而蒙对会失败）。

## 3. 坐标带着 id 走，而不是靠服务端记着「现在看的是哪块屏」

Claude Desktop 的答案是 `switch_display`：切换之后，**后续**截图跟着那块屏走。
那是服务端的一份状态。

我们不抄，理由和这个门禁其余部分是同一条：**这里什么都不缓存。** 第 3 道检查每次
动作前重读前台应用，就是因为「上一次问的时候是这样」不是「现在是这样」。一份
「当前显示器」的状态是同一个错误换个名字——两次调用之间人可以拔掉一块屏、可以
换排列，而服务端记着的那个 id 不会知道。

所以参照系跟着**坐标**走：`left_click` 和 `scroll` 各多一个可选的 `display_id`，
截图结果里明写该回填哪一个（`display_id=2`）。这也正是 Desktop 那句
「本批坐标一律指向调用前那张全屏图」的可强制版本——它靠工具描述约束模型，
我们靠参数结构承载。

**一个不存在的 id 是拒绝，不是回退到主屏。** 回退在这里读起来像贴心，实际上就是
原来那个 bug 穿了件默认值的外衣：在调用者点名之外的另一块屏上动手。

## 4. 比换算更要紧的那一条：多屏时必须点名

只做前三节，剩下的洞比补掉的还大。

模型截了第二块屏，量出 `(300, 200)`，**忘了带 display_id**。这个点同时落在主屏的
范围内（1470×956）。换算按主屏做，恒等，点击落在主屏——**F-22 原样复发**，只不过
这次是靠「没说」而不是靠「算错」。

所以：**只要这台机器不止一块屏，省略 `display_id` 就是拒绝。** 一块屏时照旧可以省
——那时只有一个正确答案，没有在猜。

这条把这次改动从「算得对」抬成「不可能悄悄算错」。代价是多屏机器上的模型必须多带
一个字段，而它得到的补偿是：**再也没有一条路径能让一次点击成功地落在别处。**

一个例外，而且是必要的例外：**`screenshot` 省略 id 时仍然给主屏，不拒绝。** 截图
没有坐标可以搞错——它**报告**自己拍的是哪块屏，而那份报告正是模型拿到 id 的唯一
来源。在这里拒绝会让 id 无从学起。看和落是两件事，规矩也不该是同一条。

## 5. 后果

**端口的契约变了，而且是不兼容地变。** `Display` 的 `origin_x`／`origin_y`
**没有默认值**。给个默认 0 会让「没想过这个问题的实现」在写它的那台机器上恰好正确、
在别处错——那正是 F-22 存在了一年的形状。仓库里三处构造点全部显式给出。

**一次拒绝的措辞分两类，这是有意的。** tier 拒绝带那句「不许绕过，永远不要用
AppleScript」，因为**权限**被拒正是模型会去找别的路的时候。坐标不在屏上不是权限
问题，是一个没有指向任何地方的数字，`off_frame` 因此**只有两段**。把反规避警告贴在
一个「你偏了一百个点」上，教给模型的是这类警告可以不读——而真正要紧的那几条就是
这么失效的。

**几何这一步排在三道权限检查之后。** 一个什么都没被批准的会话，拿越界坐标去问，
得到的是「你不在批准名单里」，不是「本机第二块屏是 1920×1080」。别人显示器的摆位
是关于那张桌子的事实，拒绝信不是发放它的地方。有一条测试专门钉这个顺序。

**F-22 关闭。** 按仓库规矩条目从 `known-gaps.md` 删除，关闭记进 `status.md`。
F-19（批准是进程级）不受影响。

**证据仍然只到算术为止。** 端到端那一半——真接两块屏，各点一次——这台机器上仍然
做不到。本 ADR 不声称做到了：能力阶梯上这条停在 **Tested**，不是 Demonstrated。

## 6. 被拒绝的方案

**统一成全局空间，让模型自己加原点。** F-22 自己列的两个可接受答案之一。拒绝的理由
是失败方向：模型要把一个只能从文本里读到的原点加到一个从图里量出来的点上，而忘记
加的后果，恰好就是今天这个 bug。带 id 的版本里，忘记带的后果是**被拒绝**。

**抄 `switch_display`。** 见 §3：服务端记着「现在是哪块屏」是这个门禁明确不做的那种
状态。

**在 `darwin.py` 里就地换算。** 最小的 diff，也是最差的位置：把唯一会算错的那段算术
放进唯一测不到的那个模块。§2 拆开它就是为了不这样。

**先接一块外接屏再修。** 这条最像稳妥，其实是把「已经错着的代码」押在一次采购上。
算术现在就能测，平台读数那一行本来就只能靠机器；等一块显示器不会让前者更可信。
