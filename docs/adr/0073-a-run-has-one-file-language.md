# ADR-073：一次运行只有一种文件语言

- 决策点：[ADR-072](./0072-a-project-is-a-directory.md) 让 Project 可以是一个真实
  目录，但至今只有 HTTP 客户端够得着它——agent 手里的 `workspace_*` 工具仍然写在
  扁平名字表上。要让能力到达 agent，是**沿用同名工具换掉后端**，还是**另起一组
  工具**；以及一个 run 会不会同时拿到两组
- 状态：**接受**。另起一组 `project_*` 工具，并且**与 `workspace_*` 每次运行互斥**：
  一个编码会话所属的项目登记了根路径，这次 turn 拿到的就是 `project_*`，否则是
  `workspace_*`。两组永不同时出现在一个模型的工具清单里
- 日期：2026-08-22
- 影响：新 `application/project_file_scope.py`、新 `adapters/tools/project_files.py`、
  `application/code_session.py` 新增 `CODE_PROJECT_TOOLS`、
  `apps/api/dependencies.py` 的 Code 组装
- 依赖：[ADR-072](./0072-a-project-is-a-directory.md)（沙箱与 `root_path`）、
  [ADR-028](./0028-task-workspace.md)（扁平名字表本身不变）、
  [ADR-025](./0025-mcp-adapter.md)（工具名在提交时被冻进授权信封）

## 1. 为什么不能沿用同名工具

最省事的做法是让 `workspace_write` 在会话有项目根路径时写目录、否则写清单。它有两
个问题，第二个是致命的。

**第一，同一个名字接受两种输入语言。** `WorkspaceName` 的字符类排除 `/`，
`project_*` 的路径必须能带 `/`。同名意味着这个工具的入参校验取决于一个模型看不见
的状态——它写 `src/main.py` 有时成功有时被拒，而两次调用长得一模一样。

**第二，授权信封冻的是名字，不是语义。** 一个 Task 在提交时把工具名写进信封
（ADR-025），此后「这次运行被允许做什么」由那份名单回答。如果 `workspace_write`
既可能是「写一条清单条目」又可能是「写本机磁盘上的一个文件」，那份名单就答不出这
个问题了——而它存在的全部意义就是能答出来。

一个已经签发的信封，其含义不该因为有人后来给项目登记了一个目录而改变。

## 2. 为什么两组必须互斥

同时给出两组，模型就要在每次写文件时选一个，而它没有依据可选：两组的描述都说
「写一个文件」。可预见的结果有两种，都不好——

- 它用 `workspace_write("src/main.py", …)`，被扁平名字的字符类拒掉，然后重试；
- 它用 `project_write("draft.md", …)`，**成功了**，于是一份本该留在清单里的草稿被
  写进了用户的仓库根目录。

第二种更糟，因为它不报错。

所以互斥不是为了清爽，是因为「这次运行在往哪写」必须有唯一答案。这个答案在 turn
开始时定下：会话所属项目有没有登记根路径。定完在这个 turn 内不再变。

## 3. 复用已有的机制，不新造一个

`WorkspaceScope` 已经解决了同一个问题：工具注册表在进程启动时建好且此后不变（这
正是「当时有哪些工具可用」对一份已写出的事件流仍然可答的原因），而「这次运行操作
的是哪个工作集」属于一次调用。它用 `ContextVar` 把「在一次调用期间」变成真的而不是
大致如此，于是一个进程里两个并发的 run 看不见彼此的工作集。

`ProjectFileScope` 是同一个形状，只是它持有的是一个 `ProjectFileStore`。没进入
scope 时它答 `None`，工具把这当作拒绝而**不是**「那就建一个」——按需建出来的东西
没有任何东西提交过、没有任何检查点指得着它。

## 4. 被拒绝的方案

**同名工具换后端。** 见 §1。

**两组都给，靠 prompt 说清楚什么时候用哪个。** 把一条不变量交给一段散文去维持。
第一次模型读错，写进去的是用户的仓库。

**只保留 `project_*`，让没有根路径的会话也用它，指向一个服务端生成的目录。**
这等于给每个会话凭空造一个目录，而 ADR-072 §4 明确拒绝过「替用户创建虚假的项目」
的同构版本。没有根路径的会话有一个完全好用的工作集，它只是不是目录。

**在信封里同时写两组名字，运行时再挑。** 那份名单于是描述了一个从未存在过的运行。

## 5. 不变量

1. **一次运行的工具清单里，`workspace_*` 与 `project_*` 不同时出现。**
2. **哪一组，由 turn 开始时会话所属项目的 `root_path` 决定，并在该 turn 内冻结。**
   turn 中途有人改了登记，不影响正在跑的这一次。
3. **`project_*` 的每一条路径都走 ADR-072 的沙箱。** 工具层不自己解释路径。
4. **没有进入 scope 时，`project_*` 拒绝，而不是创建。** 与 `WorkspaceScope` 同。

## 6. 怎么验证

- 一个没有根路径的会话，其 `allowed_tools` 里没有任何 `project_*`；一个有根路径的
  会话，其中没有任何 `workspace_*`。两条断言互为对照，缺一条就只证明了半个互斥。
- `project_write` 在未进入 scope 时返回拒绝，且磁盘上什么都没多出来。
- 越界路径经由工具调用时同样被拒——证明工具层没有绕开沙箱另开一条路。
