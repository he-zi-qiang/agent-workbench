# ADR-072：Project 是本机的一个目录

- 决策点：[ADR-071](./0071-a-project-is-a-membership-not-a-container.md) 把 Project
  定成一层可空的归属标注，存在 PostgreSQL 里。但 Code 模式的文件是一张**扁平的
  名字表**（[ADR-028](./0028-task-workspace.md)），没有目录：一个
  编码 agent 写不出 `src/agent_workbench/domain/`。要不要让 Project 变成本机上
  一个真实目录；如果要，路径边界怎么保证
- 状态：**接受**。Project 获得一个可空的 `root_path`：登记了根路径的项目，其
  Code 会话直接读写那个真实目录树。ADR-071 的归属语义**不变**——Project 仍然
  同时标注对话、任务与知识库，`root_path` 是加在它身上的一项能力，不是它的定义
- 日期：2026-08-22
- 影响：新 `domain/project_files.py`（词法检查）、新
  `adapters/filesystem/sandbox.py`（物理检查）；后续接入 Code 会话与 API
- 依赖：[ADR-071](./0071-a-project-is-a-membership-not-a-container.md)（本 ADR
  **扩展**它，不推翻）、[ADR-028](./0028-task-workspace.md)（本
  ADR 在 Code 这一个面上**不再适用**它的「名字不是路径」，理由见 §2）、
  [ADR-044](./0044-no-remote-no-production-identity.md)（`agent-api` 是环回绑定的
  本地开发进程——一个能读写本机目录的服务端，只在这个前提下成立）

## 1. 背景：扁平名字表买来的安全，是用「做不了事」付的账

`domain/workspace.py` 里那句话值得再引一次：

> a client-supplied path is exactly how path traversal and cross-tenant reads
> enter a system

它买下这条性质的方式是**根本不让路径被拼出来**：`WorkspaceName` 的字符类排除
`/` 和 `\`，`.` 和 `..` 不是合法名字。对 Task 的产物来说这是对的——一份导出的
Word 文档不需要目录。

对 Code 不是。一个编码会话要做的事就是维护一棵源码树：`src/` 下面有包，包下面有
模块，`docs/adr/` 下面有这份文件。扁平名字表能表达的最接近的东西是
`src_agent_workbench_domain_project_files.py`，那不是同一件事——它不能被 `git`
读、不能被 `pytest` 收集、不能被任何工具当成一个项目。

所以问题不是「要不要放宽一点」，是**这条性质要用另一种方式重新买下来**。

## 2. 决策：两道检查，各自防住对方防不住的

```
domain/project_files.py      词法：这条路径**说**它要出去吗
adapters/filesystem/sandbox  物理：它**实际**去了哪里
```

### 2.1 为什么必须是两道，任一道单独都不够

**只有词法检查**，会被一个符号链接击穿。`notes -> /etc` 之后，`notes/passwd`
的每一段都无辜：没有 `..`，没有绝对路径前缀，没有驱动器盘符。字符串检查看不见
链接，因为链接不在字符串里。

**只有物理检查**（realpath 后比对包含关系），原则上是够的，但它是 IO：

- 它跑不进 `domain`——那一层不做 IO，而路径合法性是领域不变量，不是适配器细节；
- 它在文件不存在时给不出有意义的答案，而写入的目标本来就还不存在；
- 一条只活在某个适配器里的规则，是下一个适配器不会有的规则。

所以两道都要，而且词法那道住在 `domain`，任何需要**早**拒绝的地方都够得着——
一个校验请求体的 API 路由，不该为了发现请求体格式错误而去碰磁盘。

### 2.2 物理检查的三条规则

**解析之后按整段比较。** `Path.resolve()` 展开路径里每一个符号链接，对尚不存在
的路径也展开已存在的前缀。比较用 `is_within`，逐段比，**不是 `str.startswith`**：
`/srv/projects/alpha-secrets` 以字符串论是以 `/srv/projects/alpha` 开头的，而它们
是两个项目。

**写入时不跟随最后一段的符号链接。** 解析发生在系统调用之前，两者之间有一个窗口：
一个能写文件的 agent 可以先埋一个链接，再让下一次写穿过去。`O_NOFOLLOW` 在内核
把这个窗口关掉。

这条规则有一个实现上的陷阱，第一版就踩了：如果把**解析后**的路径交给 `os.open`，
那么链接已经在 Python 里被跟完了，`O_NOFOLLOW` 面对的是一条没有链接的路径，什么
也拒绝不了。正确的分工是——解析后的路径用来答**包含性**，字面路径用来**打开**。
两者合起来才覆盖整条路径：中间各段靠解析，最后一段靠 `O_NOFOLLOW`。

**这套 API 不提供任何创建符号链接的操作。** 创建不了链接的 agent，利用不了上面
那个竞态。但那条 `O_NOFOLLOW` 仍然留着，因为「agent」不是唯一能往项目目录里写
东西的东西——用户有一个 shell。

### 2.3 边界是显式登记，不是任意路径

参照 Claude Desktop 的 `dispatchTrustedCodeWorkspaces`：一个路径要被**显式登记过**
才可用。包含性检查回答的是「这个路径在不在那个根里面」，永远不是「那个根是不是一个
适合交给 agent 的地方」——后者是登记时的人的判断，而登记之所以必须显式，正是为了
让那个判断有一个发生的地方。

## 3. 明确不声称的事

**这不是容器，根不是 mount namespace。** 一个本身就位于敏感位置的根，其风险等于
登记它的人所承担的风险。

**硬链接防不住，而且防不了。** 项目内一个指向项目外文件的硬链接，与那个文件**就是
同一个** inode——没有可解析的路径分量，没有可检查的标志位。缓解手段只能是登记时
就该有的那条（不要登记一个有敌意的人能写入的根），不是这个模块能加的东西。

**大小写不敏感的文件系统上，包含性比文件系统更严，而不是更松。** APFS 默认不区分
大小写，而 `Path.resolve()` 保留调用方写的大小写。于是 `Proj/a` 与 `proj/a` 在
磁盘上是一个文件、在这里是两条路径——被拒绝，不是被放行。这是可用性上的毛刺，不是
洞；没有用 `casefold()` 抹平，因为那会让比较在大小写敏感的平台上变**松**。

## 4. 被拒绝的方案

**照抄 Claude Code 的 `~/.claude/projects/<slug>/`。** 那个 slug 是把绝对路径的
非字母数字字符全换成 `-`。它**有损且不可逆**：本机上就有 `-Users-heziqiang----`、
`-----`、`-------` 三个不同目录挤在相邻的名字里，而这个仓库自己的目录
`agent工作台` 被压成 `-Users-heziqiang-agent---`（三个汉字各变一个 `-`）。一个会把
不同项目映射到同一个名字的标识符，不能用来定位状态。

**推翻 ADR-071，让 Project 就是一个目录、别的都不要。** 那会砍掉 Project 的一半：
一段对话和一个知识库住不进目录里，而「这是为哪件事做的」这个问题问的正是它们。
`root_path` 因此是**可空的一项能力**——没有登记根路径的项目照常工作，就像今天一样。

**把根路径放进配置文件。** 那样「有哪些项目」这个问题就有两个事实源，而其中一个
不在 PostgreSQL 里（配置不变量：PostgreSQL 是事实源）。根路径是项目行上的一列。

**让扁平名字表支持 `/`。** 那是把 ADR-028 的性质丢掉却不承认——`WorkspaceName`
的字符类是 Task 产物那条链路的安全前提，Task 的重放语义建立在「名字不是路径」
之上。Code 需要目录，Task 不需要；两条链路分开，比让一条假装成另一条要诚实。

## 5. 不变量

1. **两道检查都必须跑，顺序固定。** 词法在前（免费、全域、且保证物理检查永远不会
   收到含 NUL 的字符串），物理在后。
2. **打开的是字面路径，比较的是解析后的路径。** 见 §2.2。任何把两者合并成一个
   返回值的「简化」都会让 `O_NOFOLLOW` 失效。
3. **包含性按整段比较。** 永不使用 `str.startswith`。
4. **根必须显式登记。** 没有「默认根」，没有从当前工作目录推断出来的根。
5. **`root_path` 可空，且空是正常状态。** ADR-071 的第 3 条不变量在这里继续成立。
6. **一次整文件替换要么落在一个本回合读过全文且未变的文件上，要么落在一个不存在的
   路径上。** 由 [ADR-078](./0078-a-file-you-have-not-read-is-not-yours-to-overwrite.md)
   加入。前五条挡的是「写到根外面去」；这一条挡的是根**里面**的一次静默损失——路径
   全部合法，沙箱全程放行，被覆盖的是用户自己刚写的东西。

## 6. 怎么验证

- 词法半边：`tests/domain/test_project_files.py`，按**攻击意图**分组而不是按分支
  分组——`..` 在任意位置、绝对路径、盘符、NUL、控制字符、Windows 保留名、一个文件
  两种拼法（`.`／空段／NFC 与 NFD）、各项上限。另有一组「必须仍然能用」的路径，
  因为一个把真实源码树也拒掉的沙箱是一堵墙不是沙箱。
- 物理半边：`tests/adapters/test_project_sandbox.py`，每一条都是词法半边**放行**的
  输入——如果某条测试改 `domain/project_files.py` 就能通过，它就放错了文件。覆盖
  单跳链接、链接链、指向内部的链接（必须放行）、叶子链接（读写都必须拒绝，即使它
  解析后仍在根内）、根本身是链接、以及名字前缀相邻的兄弟目录。
- **验证过是有牙的**，三条都实际跑过而不是设想：
  - 把 `open_for_write` 改回打开解析后的路径 →
    `test_the_leaf_symlink_is_refused_on_write_even_though_it_resolves_inside` 失败，
    且**只有它**失败。这正是不变量 2 的价值所在：那次「简化」不会惊动其余 68 条。
  - 把 `is_within` 换成 `str.startswith` → 两条失败，
    `test_a_sibling_whose_name_is_a_prefix_is_outside`（端到端）与
    `test_a_name_prefix_is_not_containment`（纯函数）。两层各有一条守着同一条规则。
  - 把 `segments` 换回 `PurePosixPath(...).parts` → 四条「一个文件两种拼法」失败。
    这一条不是构造出来的：`.parts` 会自己吃掉 `.` 和空段，所以第一版的那两项检查
    从来没有触发过，是它们的测试把它抓出来的。
