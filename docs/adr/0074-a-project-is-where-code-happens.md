# ADR-074：Project 是编码发生的地方，而不是一层横跨产品的标注

- 决策点：[ADR-071](./0071-a-project-is-a-membership-not-a-container.md) 把 Project
  定成一层可空的归属，横跨对话、任务与知识库；[ADR-072](./0072-a-project-is-a-directory.md)
  又给它加了一个可空的目录。两条可空叠在一起，产生了一条没人能走通的路：要让 Code
  用上文件夹，得先去「项目」页建一个项目（那页没有设置目录的入口）、再调 API 登记
  路径、再回 Code 把会话归过去。要不要把 Project 收进 Code
- 状态：**接受**，并**推翻 ADR-071 的产品形状**。Project 就是一个编码工作区：
  一个有名字的目录。它在 Code 里创建和切换，不再有独立的「项目」页；一个编码会话
  **必须**属于一个 Project，没有文件夹就开不了会话
- 日期：2026-08-22
- 影响：删除 `web/src/features/projects/`、导航去掉 `/projects`、Chat 与 Code 的
  `ProjectPicker` 下线；Code 的起始屏改为选择或新建文件夹；ADR-071 §2.1／§2.3 的
  跨产品归属不再是产品的一部分
- 依赖：[ADR-072](./0072-a-project-is-a-directory.md)（沙箱与 `root_path` 不变）、
  [ADR-073](./0073-a-run-has-one-file-language.md)（互斥的两组工具——本 ADR 让
  `project_*` 成为 Code 的**唯一**一组，见 §4）、
  [ADR-047](./0047-a-session-is-named-by-its-first-sentence.md)（会话仍由第一句
  指令命名，本 ADR 不改）

## 1. 背景：两条可空叠在一起，等于一条走不通的路

ADR-071 的核心论证是对的，而且我仍然认为它当时是对的：人不按产品想事情，同一个季度
复盘会同时有三段对话、两个任务和一个编码会话。可空是那份论证的关键一步——不替用户
凭空造项目，没有归属就照实显示成没有归属。

ADR-072 在它上面又加了一层可空：项目**可以**有目录。

两条可空相乘，产生了四种状态，而其中只有一种能干活：

| 有项目？ | 有目录？ | Code 能用文件夹吗 |
|---|---|---|
| 否 | —— | 否 |
| 是 | 否 | 否 |
| 是 | 是，但会话没归过去 | 否 |
| 是 | 是，且会话归过去了 | 是 |

而到达第四行要经过三处不同的界面，其中一处（项目页）**根本没有设置目录的入口**——
那个能力只存在于 API 上。这不是「功能没做完」，是这套模型把一件本该是一步的事拆成了
三步，而且第一步在界面上不可能完成。

CLI 那边同一件事是一条命令：`agent-cli project use`，在目标目录里跑，什么都不用选。
两边差这么远，说明差的不是界面工作量，是模型。

## 2. 决策：Project 就是编码工作区

```
Project = 一个有名字的目录
  └─ 若干编码会话，每一个都属于它
```

**一个编码会话必须属于一个 Project。** 没有文件夹就开不了会话，和 CLI 一致——在
CLI 里你不可能「没有 cwd」。这条是为了让「产物在哪」永远有确定答案：现在它只有一个
答案，就是那个目录。

**Project 在 Code 里创建和切换。** 起始屏就是「选一个文件夹，或新建」。不再有一个
需要先去别处完成的前置步骤。

**没有独立的项目页。** 导航里那一项去掉。

## 3. 这推翻了 ADR-071 的什么，以及没推翻什么

**推翻的**：Project 作为横跨对话／任务／知识库的一层归属。对话和任务不再能归到项目
下，`ProjectPicker` 从 Chat 与 Code 的头部下线。ADR-071 §1「产品回答这是什么工具，
Project 回答这是为哪件事」——那个「另一个维度」的主张，本 ADR 放弃了。

放弃的理由不是它讲错了，是它**没有兑现**：那层归属除了在两个下拉框里被设置，从未被
任何界面用来把三样东西放到一起看。一个只能被设置、不能被使用的维度，不是维度，是
两个下拉框。

**没有推翻的**：

- **不替用户造项目**（ADR-071 §2.1）。仍然成立，而且更重要了：现在项目有目录，凭空
  造一个意味着凭空指向某个文件夹。新建项目永远是人选了一个文件夹之后的事。
- **删除项目不删除它标注的东西**（§2.2）。`ON DELETE SET NULL` 不变，而且现在还多
  一条：删除项目**不碰磁盘上的任何文件**。
- **owner-private**（§2.4）。不变，一个字都没加。

## 4. 一个连带后果：Code 只剩一组文件工具

[ADR-073](./0073-a-run-has-one-file-language.md) 让 `workspace_*` 与 `project_*`
每次运行互斥，哪一组取决于会话所属项目有没有目录。既然现在**每个编码会话都必须有
目录**，那个条件恒真，Code 永远拿到 `project_*`。

ADR-073 的互斥机制**不删**，理由有两条：Task 那条链路仍然只有 `workspace_*`，而互斥
本身是防止两组同时出现的那道闸——闸的价值不因为一侧暂时永远为真而消失。真正变化的
是 `CODE_TOOLS` 不再是任何运行的工具清单，而这件事应当由一条测试说出来，不是靠读者
推断。

## 5. 被拒绝的方案

**只在 Code 里加一个「选文件夹」按钮，项目页原样留着。** 那样两处都能建项目，而它们
建出来的是不同的东西——项目页建的没有目录，Code 建的有。同一个列表里两种项目，其中
一种在 Code 里点开会失败。

**保留跨产品归属，只是把入口挪进 Code。** 那没有解决四种状态那张表，只是把第一步换
了个地方。而且「在 Code 里给一段对话设置归属」是个奇怪的操作。

**让会话可以没有文件夹，退回扁平工作集。** 那正是 §2 那条不变量要消除的东西：「产物
存哪了」会有两个答案，而人问这个问题的时候通常已经在找不到东西了。

## 6. 已有数据怎么办

`conversation_sessions.project_id`、`task_runs.project_id` 与
`project_knowledge_bases` 三处**保留，不迁移，不删列**。

这一条是 ADR-071 §2.2 的直接延续：那些行里存着人做过的判断，而一次产品形状的改变
不该顺手把它们删掉。界面不再写它们，也不再读它们；`PATCH /v1/chat/sessions/{id}/project`
与 `PATCH /v1/tasks/{id}/project` 仍在，因为下线一个端点和删一列数据是同一种破坏的
两种形式。

代价是诚实记下来的：库里会有一些没有任何界面在用的列。它们会出现在
[known-gaps](../known-gaps.md) 里，而不是假装不存在。

## 7. 不变量

1. **每个编码会话都属于一个 Project，且那个 Project 有 `root_path`。**
2. **新建 Project 必须伴随一个人选定的目录。** 没有「先建了以后再说」的项目。
3. **删除 Project 不删除磁盘上的任何东西。**
4. **路径规则仍然只有一处**（ADR-072 的沙箱），本 ADR 不新增任何路径处理。

## 8. 怎么验证

- 起始屏在没有项目时给的是「选一个文件夹」，而不是一个可以直接输入的输入框——
  一条断言钉住没有文件夹时**不能**提交。
- 新建项目的请求里 `root_path` 必填；缺它的请求被拒。
- 导航里没有 `/projects`，且深链 `/projects` 不再解析到一个页面。
- ADR-073 的互斥测试保留，另加一条：Code 的工具清单里没有任何 `workspace_*`。
