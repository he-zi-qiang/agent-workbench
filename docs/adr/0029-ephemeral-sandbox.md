# ADR-029：沙箱是纯函数，断网是它保持纯的原因

- 决策点：Agent 能不能跑代码；跑代码这件事怎么不把前面几条 ADR 的重放保证全部作废
- 状态：**接受**
- 日期：2026-08-09
- 影响：新增 `apps/sandbox_mcp/`；新增 `run_python` 工具；依赖一个容器运行时；
  `ArtifactRef`、`ToolGateway`、`CANONICAL_V1_NODE_IDS`、ADR-009 **均不变**
- 依赖：**ADR-028 必须先落地**——沙箱的输入输出没有工作区就没有落脚点

## 1. 背景

ADR-028 给了 Agent 一个能积累产物的地方，但它仍然只能靠模型自己"想"出内容。凡是需要
**算**的事情它都做不了：把三份 CSV 合并、从 20 页 PDF 里抽出表格、生成一张图、验证自己
刚写的 JSON 是不是合法。

这些是 Agent 实际干活时最常撞上的一类需求，而它们有一个共同点：**用代码做又快又准，用
模型做又慢又会编**。ADR-020 已经在另一个场景上记录过同一件事——不让模型读到真实页面时，
同一个天气问题三次跑出三个不同的温度。让模型"心算"一份 CSV 的汇总是同一种错误。

## 2. 为什么跑代码通常会毁掉一切

一个能执行任意代码的工具，默认会把这套系统所有的重放保证一次性作废：代码可以发网络
请求、可以写主机文件系统、可以留下进程。任何一条成立，"这次调用可以安全重放"就不再成立，
ADR-027 那条"只读取外部世界，写只写进自己的 artifact"的线也就直接被跨过去了——因为
`requests.post(...)` 就在那儿。

所以本 ADR 的全部内容其实是一件事：**把执行约束到它是一个纯函数为止**。

## 3. 决策

### 3.1 沙箱是纯函数：文件进、文件出

```
run_python(script, inputs) -> {stdout, stderr, exit_code, outputs}
```

一次调用创建一个容器、执行、销毁。没有跨调用的状态，没有会话，没有"上一次跑到哪儿"。

`inputs` 是 `{名字: 字节}`，`outputs` 同形状。Task 侧的工具负责从 ADR-028 的工作区读出
输入、把输出写回去；**沙箱自己不认识工作区、租户和所有者**。

这一点直接沿用 ADR-026 立的规矩：MCP server 不接收路径或所有者字段。`word_mcp` 是内容进
字节出，沙箱是文件进文件出，形状一致，安全属性也一致——一个不知道租户是谁的进程，无法
把东西写到别的租户名下。

### 3.2 断网不是加固项，是这条 ADR 成立的前提

容器**没有网络**。这不是"再收紧一点"的可选项，它是让上面那句"纯函数"为真的唯一原因。

有网络的沙箱可以 POST，可以下单，可以改变对面的状态——那一刻 ADR-027 的分界线就没了，
`retryable_effects=true` 不再站得住，重放保证全部作废。**需要联网的取用走 ADR-027 的
只读工具**，那条路径有 SSRF 闸门、有事件记录、有授权信封；沙箱不复制这条能力。

其余隔离一并写死，不做成配置项：只读根文件系统、tmpfs 作为可写层、非 root 用户、
丢弃所有 capability、禁止提权、无主机挂载、内存与 CPU 上限、墙钟超时、进程数上限。

### 3.3 有界，并且超界是错误而不是截断

单个输入文件、输入总量、`stdout`/`stderr`、单个输出文件、输出总量、输出文件数——各自
有上限。超界返回结构化错误。

不截断，理由和 ADR-028 §3.4 一样：截断的输出是坏输出，而下一步会把它当成好输出读走。

### 3.4 重放安全，以及它的准确边界

同一个入口工作区版本 + 同一段脚本 = 同一批输出，因为容器是全新的、断网的、没有历史的。
所以这个工具是 `idempotency="safe"`，不带 `operation_key`。

**准确边界**：脚本自己可以是不确定的——`time.time()`、`random`、字典迭代顺序。本 ADR
不消除这一点（不注入固定时钟、不设 `PYTHONHASHSEED`），因为那会让一批合理的脚本行为
变得反直觉。重放得到的是"一次同样合法的执行"，不是"逐字节相同的输出"。

这个区别是可以接受的，因为输出只落进版本化的工作区，没有外部效果——但它必须写下来，
不能让人以为这里有字节级确定性。真需要确定性的产物（比如 ADR-026 的 docx）由渲染器
自己保证，不靠沙箱。

### 3.5 风险声明与暴露范围

`risk="external"`（它把内容交给了一个本进程之外的执行环境）、`concurrency="exclusive"`、
`permission_scopes=("sandbox:run",)`、`idempotency="safe"`。

先只给 `writer/synthesize`，与 ADR-028 一致。

### 3.6 容器运行时是部署前提，缺了就没有这个工具

Worker 启动时探测一次运行时。不可用 → 记结构化日志、不注册这个工具、**进程照常启动**，
与 ADR-025 对连不上的 MCP server 的处理一致。

一个没有容器运行时的部署会少一个能力，而不是起不来。

## 4. 后果

- Agent 能算、能转换格式、能验证自己的产物，而不是全靠"想"；
- 这是本轮几个 ADR 里**唯一引入新部署前提**的一个（容器运行时）。它换来的能力最大，
  代价也最实：没有它就没有这个工具；
- 隔离是实打实的工程，不是配置。它需要真正的验证测试，而不是"我们设了个 flag"——
  验收里必须包含**尝试联网并断言失败**、**尝试写只读根并断言失败**、**超时被杀掉**；
- **不解决**：跨调用状态、长时间运行的服务、GPU、沙箱内联网、字节级确定性重放。

## 5. 备选方案

**在 Worker 进程里用 `subprocess` 跑。** 没有隔离。模型生成的代码与 Worker 共享文件系统、
网络和凭据——包括 provider key。不可接受。

**给沙箱开一个"受控"的网络出口（比如只允许某些域名）。** 允许列表会随需求增长，而
每一次放宽都在削弱 §3.2。真要联网就走 ADR-027 的只读工具，那里有闸门。

**用一个第三方远程代码执行服务。** 省掉运行时依赖，代价是把模型生成的代码和工作区内容
送到第三方，并且引入一个新的信任边界。本地容器的隔离属性是可验证的，远程服务的不是。

**支持任意语言。** Python 覆盖了这个 Agent 的绝大多数需求；每加一门语言就是一套新的
运行时、依赖管理和隔离验证。需要时再单独决定。
