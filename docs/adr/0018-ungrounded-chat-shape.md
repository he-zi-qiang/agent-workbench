# ADR-018：无接地对话是显式形态，自动切换按证据而不是按问题

- 决策点：Chat 交互形态；`chat.retrieval_shape` 的取值集合
- 状态：**接受**
- 日期：2026-08-03
- 影响：config schema `1.2` → `1.3`

## 背景

试用控制台时提出的问题：Chat **只能**在知识库里对话，没有直接和模型说话的路径。

这不是界面漏了一个开关。它被三层同时挡着，而且每一层都是有意写成这样的：

| 层 | 位置 | 现状 |
|---|---|---|
| API 契约 | `AskRequest.knowledge_base_id: Identifier` | 必填，无默认 |
| 发布边界 | [前端设计基线](../frontend-design.md) | `ModelCompleted.text` **永不**成为答案；正文只来自 `AnswerCommitted`、`AnswerWithheld` 或同步 `AskResponse` |
| 配置类型 | `chat.retrieval_shape: Literal["fixed", "agentic"]` | 单一集合，没有第三个值 |

第三层决定了这件事的性质。PR-055 遇到过同一个形状的请求——给
`runtime.executor` 加一个 `"fake"` 值——当时的结论是：**单值 `Literal` 编码的是一条
已冻结的不变量，加一个取值等于推翻它**，按项目规矩要先写 ADR、升 config schema
版本，不是顺手加个开关；并且留了一条正面钉住它的测试。这份 ADR 就是那条规矩要求的
前置动作。

## 问题

真正要回答的不是"能不能加个开关"，而是：**一个没有证据的答案，凭什么可以出现在一个
以"答案只在证据与权限复核通过后发布"为卖点的系统里。**

含糊处理有两种，都不能接受：

- **把它做成"检索返回空"**。固定两步路径在没有证据时给出的是拒答文案，因为那条路径
  的前提是"答案建立在检索到的段落上"。让它在无证据时改口去自由回答，等于让**同一个
  发布语义**有时表示"这句话有据可查"、有时表示"这是模型自己说的"，而读者分不出来。
- **在界面加个开关，直接显示 `ModelCompleted.text`**。这会一次性推翻前端设计基线里
  那条最值钱的边界。届时"本系统的答案都经过发布门"这句话会变成假的，而且是**在演示
  里就为假**。

## 决策

**`chat.retrieval_shape` 增加两个取值 `ungrounded` 与 `routed`，config schema 升到
`1.3`。** 形态在配置层显式存在，而不是靠请求里少传一个字段推断出来——一个由"字段缺失"
触发的模式，是没人复核过的模式。

**`routed` 是"先检索、拿不到证据再由模型回答"，切换依据是*授权后的证据*。** 这一条是
本 ADR 初稿明确拒绝过的（当时的措辞是"形态不能被推断"），修订理由写在这里而不是靠后
人考古：被拒绝的是**由请求字段缺失推断形态**，而 `routed` 不是那个——形态仍然是配置里
写死的一个值，每次运行都走同一条代码路径；变化的是那条路径**内部**的一次判断，而且这
次判断的结果**被记录**（`ChatTurnResult.grounded` 与它自己的终态事件）。"没人复核过的
模式"之所以危险，是因为它不留痕；留痕的分支不是那种东西。

切换依据必须是**授权后**的证据，不能是问题本身。用分类器或让模型自己决定，会出现"知识
库里明明有、却按记忆回答"——那正是 RAG 要防的失败，而且要多花一次模型调用才能犯。按检索
结果切换则相反：能接地就接地，无接地只是空结果的兜底。

一个必须写下来的后果：**被 ACL 过滤掉的证据与"根本没有证据"在这里长得一样**，因此无权
读某文档的人得到的是一个普通的无接地回答，而不是拒绝。这是故意的——拒绝会告诉对方"存在
一份你不能读的文档"。

**这条路径永不产生 `Citation`。** 不是"通常没有"，是结构上不可能有：它不经过
`RetrievalService`，没有 `ContextPacket`，没有 `authorized_revisions`。引用围栏要求
模型**点名**且**被展示过**才给引用，无接地路径两个条件都不成立，因此它返回的
citations 恒为空元组。**空引用是这条路径的正确输出，不是缺陷。**

**它有自己的发布事实，不复用 `AnswerCommitted`。** 新增
`UngroundedAnswerCommitted`。理由是复用会把两件不同的事记成同一件：`AnswerCommitted`
的含义是"这个答案建立在当时可读的这些 revision 上，且复核通过"，而无接地答案没有任何
revision 可以复核。让审计日志把两者混为一谈，等于把发布门的证据价值也一并抹掉——一条
读者无法区分来源的记录，比没有记录更糟。

**`knowledge_base_id` 只在 `ungrounded` 下可省略。** `fixed`、`agentic` 与 `routed`
都仍然必填——`routed` 尤其必填，因为它**先检索再决定**，没有知识库就没有可判断的依据，
那时它就只是 `ungrounded` 换了个名字。省略不是放宽，是**换了一条不同的路**：请求里带了
知识库却选了 `ungrounded`，是配置与请求互相矛盾，按失败关闭拒绝，而不是"忽略其中一个"。

**界面必须持续标注它未经证据核实**，而不是发送前提示一次。标注跟着**消息**走，不跟着
会话状态走：会话可以切换形态，切换之后早先那些消息的性质并不改变，而一个只描述"当前
模式"的标签会在切换的一瞬间把历史消息也重新描述一遍。

## 后果

- `AskRequest.knowledge_base_id` 变为可选，并新增跨字段校验：非 `ungrounded` 形态缺
  它仍然是 422；`ungrounded` 形态带它也是 422；
- 能力表里 Chat 一行必须分开表述：**RAG 对话有引用与发布门；无接地对话两者都没有**。
  合并成一行"支持对话"会让读者把前者的保证套到后者头上；`routed` 更要说清楚——同一个
  会话里两种回答都会出现，所以标注必须跟着**消息**走；
- 简历叙事不变，但**多一句限定**："答案只在证据与权限复核通过后发布"这句话，适用于
  RAG 路径，不适用于显式开启的无接地路径；
- ADR-013、ADR-016、ADR-017 不受影响：这条路径根本不进入检索层；
- `runtime.executor` 那条不变量**不受此先例影响**。这里放宽的是"对话可以没有证据"，
  不是"Tool Loop 可以有第二个所有者"；两者都是单值 `Literal`，但编码的不是同一件事。

## 重审条件

如果无接地路径开始需要工具、需要多轮记忆预算、或者有人要求它也给出引用，那说明它正在
长成第二个 Chat 实现。届时应当重新评估：要么把它合回检索路径，要么给它自己的工作包，
而不是继续在同一个 `TurnExecution` seam 下面加分支。
