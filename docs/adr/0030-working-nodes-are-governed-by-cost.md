# ADR-030：会干活的节点由成本和时限管，步数只当兜底

- 决策点：一个带工具迭代的 Agent run 该由什么约束；`max_steps` 的域上限 100 还合不合适；
  工作区只能整文件覆写够不够用
- 状态：**接受**
- 日期：2026-08-09
- 影响：`RunBudget.max_steps` 域上限放宽并改为兜底；`max_cost_micro_usd` 与 `deadline`
  从"存在但没人用"变成工作节点的主约束；新增 `workspace_edit` 与 `workspace_grep`；
  `config_schema_version` 抬一版
- 依赖：ADR-028（工作区）、ADR-029（沙箱）

## 1. 背景

ADR-027 到 029 给了 Agent 手脚。这份 ADR 处理的是一个很容易被跳过的问题：**手脚齐了，
它仍然干不了活**，因为运行预算是给"回答一次"设计的，不是给"干一件事"设计的。

今天的数字：

```python
max_steps: int = Field(ge=1, le=100)     # 域模型硬上限 100
max_cost_micro_usd: int | None = None    # 存在，默认没人管
deadline: AwareDatetime | None = None    # 同上
```

配置默认 `max_steps = 12`。

把工作区、沙箱和取网页接上之后，一个写作节点的真实轨迹是这样的：列一下工作区、读三个
输入、跑一段脚本、**看到报错**、改脚本、再跑、读结果、写草稿。这里已经八九步，而它一个
字还没交付。12 是墙，而 `le=100` 意味着**连配都配不上去**。

更根本的是：今天真正约束一个 run 的只有步数。成本和时限两个字段存在但默认是空的，也就是
说一个 run 花了多少钱、跑了多久，系统并不管。对"一次问答"这没问题——一次问答的成本方差
很小，步数是个够用的代理。对一个会迭代的节点，这个代理坏掉了：第 3 步可能读了 200 字节，
第 7 步可能读了 200KB，**用步数管它们等于假装两者一样贵**。

## 2. 决策

### 2.1 工作节点由成本和时限管，步数降为兜底

`max_cost_micro_usd` 与 `deadline` 成为工作节点预算的主约束，必须被设上。`max_steps`
保留，但它的角色改变：它不再是"这个节点该做多少事"的表达，而是**防失控循环的兜底**——
一个反复提同一个调用的 run 不该跑到把钱花光才停。

`RunBudget.max_steps` 的域上限从 100 放宽。放宽多少不是这份 ADR 该定死的数字，但它必须
大到"一个真在迭代的节点不会撞上它"，否则兜底就又变回了主约束。

**为什么不是简单地把 12 调到 200**：那样只是把墙挪远，没有回答"什么该停下它"。花光预算
之前停不下来的 run，和步数用尽才停的 run，区别只在你事后看到的是哪个错误。成本和时限
是使用者真正在意的两件事，也是唯一能跨不同工作形态比较的两件事。

### 2.2 额度用尽的行为不变

ADR-022 已经决定过：工具额度用尽 → 收走工具、让模型用手上的东西作答；步数/token/成本/
deadline 用尽 → 结束 run。这条**一个字不改**，本 ADR 只是让后一组里成本和 deadline 真
的会先到。

### 2.3 `workspace_edit`：不能只有整文件覆写

ADR-028 给的 `workspace_write` 是整文件写。这在小文件上够用，在稍大的文件上**不是预算
问题而是不可能**：改一行要让模型逐字复述整个文件，一个两千行的文件根本复述不完，而复述
错一个字符就是静默的数据损坏。

```
workspace_edit(name, old_text, new_text) -> 新版本
```

**匹配数不是 1 就失败。** 零处匹配是"模型以为文件是那样但不是"；多处匹配是"模型以为只
有一处但不止"。两种都必须返回结构化错误而不是猜——静默改错地方比不改坏得多，而且不会
留下任何痕迹。这条与整个代码库的取向一致：schema 不认识的关键字拒绝而不是忽略，超界返回
错误而不是截断。

### 2.4 `workspace_grep`：名字不够，得能搜内容

`workspace_list` 只给名字。一个在几十个文件上干活的 Agent 需要"哪个文件里提到了 X"，
否则它只能把文件一个个读进上下文——那正是上面说的那种昂贵的步数。

```
workspace_grep(pattern, name_glob?) -> (名字, 行号, 该行) 的有界列表
```

有界：结果条数、每行长度、扫描字节数。正则由固定引擎执行并带超时，pattern 来自模型，
是不受信任的输入——一个灾难性回溯的正则不该能挂住 Worker。

## 3. 后果

- 一个带工具的节点第一次能真正迭代到把活干完，而不是撞上一个为问答设定的步数墙；
- **成本从"没人管"变成"必须设"**。这是收紧不是放松：今天一个 run 可以花掉任意多钱而
  没有任何配置拦它；
- `workspace_edit` 让大文件上的增量修改成为可能，这是这套工具能不能实际用起来的分界；
- 预算语义变了意味着**既有 run 的账会变**：设上 deadline 之后，一个慢但步数不多的 run
  可能第一次因超时结束。这是本 ADR 的直接后果，不是回归；
- **不解决**：跨节点的总预算（`max_agent_invocation_attempts_per_task` 仍是那道闸）、
  按工具分别计价、预算用尽时的部分成果保留。

## 4. 备选方案

**只把 `max_steps` 调大。** 最省事，也是最容易选的。它把墙挪远而不回答什么该停下 run，
并且让"这个节点花了多少钱"继续没人管。

**按 token 管。** `max_total_tokens` 已经存在，比步数好，但它仍然不是使用者在意的单位，
而且不同 profile 的单价不同，同样的 token 数可以差好几倍钱。

**让 `workspace_write` 支持按行号替换。** 比字符串匹配脆：模型看到的行号来自它上一次读
文件的那一刻，中间任何一次写入都会让行号失效，而失效的方式是静默的。字符串匹配至少在
文件变了的时候会匹配失败。

**让 `workspace_edit` 在多处匹配时改第一处。** 这是大多数编辑器的默认行为，在这里是错的：
模型并不知道有多处，"第一处"对它是随机的。
