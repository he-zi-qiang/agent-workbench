# ADR-0119：最后一步用来写报告；那一页允许两个操作者，面板上写着它在哪

- 状态：Accepted
- 日期：2026-09-13
- 关联：ADR-0117（人可以操作浏览器——§2.1 的仲裁规则被本 ADR 撤换）、ADR-0113（受控浏览器，§4 的
  「两个操作者」问题在这里得到第二个、也是能用的答案）、ADR-0116（重复的调用按记录作答——它让步数
  上限不再是防跑飞的主力）、ADR-0118（大文件分段写——它让一轮的步数天然变多）、ADR-022（工具额度
  与步数互相独立）

## 1. 背景

第八十六批的实测（`ses_a42b…`）一次跑出了三件事，用户三句话点名了其中两件：

> 请你修改上面的bug
> 还有问题，浏览器应该显示所在机器的文件路径，然后还存在浏览器状态一直被控制，人无法操作的状态

1. **步数用尽的一轮把自己做过的事一起扔了（F-45）。** 那一轮分八段写出 `mario.html`（31,928 字节）、
   用 `python3` 核对了 15 行关卡、在浏览器里打开页面并**改掉三个真 bug**，在测金币收集时撞上
   `max_steps=60`：`RunFailed`，`output_text` 是空的。控制台上只有一个上限的名字；会话历史里
   什么也没有（`code_session.py` 只在 `output_text` 非空时追加助手消息），所以下一轮的模型不知道
   文件已经写好了，第一件事仍然是「先把项目重读一遍」。**做过的事在磁盘上，在这套系统里不可见。**
2. **面板不说这一页是哪个文件。** 帧那条路由只回一张 JPEG。读者看着一个渲染出来的页面，没有任何
   办法知道它是 `mario.html` 还是别的什么，更不知道它在哪台机器的哪个路径上——而在容器栈里那是
   浏览器容器内部的路径，人没有第二条路看到它。
3. **「浏览器状态一直被控制」。** ADR-0117 §2.1 的仲裁是「有编码回合在跑就 409」。实测里那一轮跑了
   **246 秒**，而人想按方向键的正是那几分钟——模型刚把页面打开、游戏正在那里跑。于是这块面在它
   唯一有用的时刻永远答「等这一轮结束再点」。ADR-0117 §3 写着「粗的规则是对的规则」，那句话是在
   还没有实测的时候写的；有了实测，它是错的。

### 1.1 对照 Claude Code

| | Claude Code | 本仓库（本 ADR 之前） | 本 ADR |
|---|---|---|---|
| 步数用尽 | 没有步数上限的概念（`--max-turns` 到了就停），整份 transcript 留在上下文里 | `RunFailed`，报告没写成，会话历史里不留东西 | 最后一步预留给报告：还是失败，但报告随 `output_text` 出来 |
| Browser 面板 | 人随时可以点、可以打字；模型自己重新截图/读页 | 有回合在跑就 409 | 两边都能动，模型在下一次浏览器调用上被告知页面被人碰过 |
| 面板显示地址 | 有标签页、有 URL | 只有一张图 | 帧上带 `X-Browser-Url`，面板画出来 |

## 2. 决定

### 2.1 最后一步用来写报告，而不是用来干活

- `RunBudget.report_turn_due(usage)`：`max_steps >= 2 且 usage.steps >= max_steps - 1`。这是预算的
  **第四个问题**——前三个是「有没有超」「能不能再开一轮」「能不能再派发工具」，这个是「剩下的这一步
  该不该用来交代」。
- 运行时在循环顶端问它，**排在 `halt_reason_for` 之后**：跑完时间、token、钱的一轮也没有东西去写
  报告，只有**步数**是这套运行时自己发出来的、用来给循环封顶的单位，所以它能留一步。留一步而不是
  多给一步：一轮仍然正好花掉 `max_steps`，没有任何上限被突破，循环的界还是原来那个数。
- 只在这一轮**本来还有活可干**时才留：工具额度已经花光（ADR-022）或者工具被收走（ADR-0116）的那一轮，
  按它们自己的规则本来就是「不带工具的作答轮」并且以 `completed` 结束；在那之上再留一步，等于把一个
  做完了的运行重新标成「步数不够」。
- 预留的那一轮：请求不带任何工具，消息末尾追加一条用户消息（`_CLOSING_NOTE`）说明——没有工具、
  写报告、说清改了什么在哪、验了什么、还差什么、下一轮先做什么。
- 这一轮**仍然以失败结束**（`stop_reason=max_steps`），因为活没干完，而一个步数用尽的 Task 节点不能在
  它的图里看起来像答完了的。变的是**报告出得来**：`_failed` 把 `ledger.answer` 当作 `output_text` 交出，
  控制台画它，编码会话把它追加进下一轮要读的历史。
- Code 会话的三个默认值按实测放大：`max_steps` 60 → 120，`max_tool_calls` 120 → 240，
  `turn_timeout_seconds` 600 → 900。理由写在 `settings.py` 那段注释里：ADR-0118 要求大文件分段写
  （段数就是调用数），浏览器验证是「打开、读、求值、操作」每个结论好几步，而防跑飞自 ADR-0116 起
  由「重复按记录作答、两次之后收走工具」承担——步数上限回到它本来的角色，一个诚实的活干不到的兜底。

### 2.2 那一页允许两个操作者，模型被告知

- **删掉 409。** `POST /v1/browser/input` 只剩两道拒绝：没有 `mcp:browser` 是 403，浏览器不在是 503。
- **回合数作为事实回给人**：应答多一个 `turns_in_flight`，面板在它 > 0 时说「送进去了。模型这一轮也在
  动这个页面，画面可能会自己变」。同一个数字，从拒绝的理由变成一句提醒——**决定权回到人手里**。
- **模型被告知**：`browser_interact` 多一个 `by_person` 参数（控制台转发人的手势时设，模型不设），
  浏览器会话按落地的动作计数，**下一次**模型的浏览器调用的结果末尾追加一行：有人直接操作了这一页
  （几个动作），你上一次 snapshot 的 ref 可能已经指向别的元素或者不存在了，动 ref 之前先重新
  snapshot。读一次就清掉：这是关于某个时刻的事实，每次都说的话就没人读了。
- 这正是 ADR-0113 §4 要的那套仲裁的第二个答案，而且是能用的那个：**不是锁，是一句话**。

### 2.3 面板上写着这一页在哪

- 浏览器会话多一个 `current_url()`（`about:blank` 算没有）；`/frame` 在图上带 `X-Browser-Url`，
  百分号编码好让带中文的路径过得了 latin-1 的头；API 那条只读转发原样带过去。
- 控制台在画面底下画一行：`file://` 的去掉协议头只留路径，其余原样；百分号编码在这一层解开——
  `/projects/windows%E6%B5%8B%E8%AF%95/mario.html` 谁也认不出来。
- 地址和图是**同一次应答**带来的，不是另开一条路由去问：隔一次轮询取回来的地址可能描述的是另一页。

## 3. 为什么是这些做法

- **为什么报告轮仍然是失败**：这套运行时也跑 Task 图的节点。把步数耗尽改成 `completed`，一个没干完
  的节点在它的图里就和答完了的一样，导出会把半截结果当成答案。「失败，但话说完了」是真话。
- **为什么是预留而不是多给一步**：多给一步的话，`max_steps=3` 的一轮会花掉 4 步，上限就不是上限了；
  而且每加一种「例外」都要在别处解释一次。预留不改变任何已有的数。
- **为什么不给截止时间也留一步**：留了也没有时间去跑那一次调用。deadline 是唯一一个连报告都买不起的
  上限，它照旧当场结束（测试守着这条界线）。
- **为什么锁换成一句话**：一个页面同时只有一个操作者，这一点没变；变的是**谁来保证**。锁靠系统保证，
  代价是人在那几分钟里完全动不了；一句话靠模型保证——它本来就要在动 ref 之前重新 snapshot，
  `_refs` 那个「不是最近一次 snapshot 的 ref」检查一直都在。Claude Code 的 Browser 面板就是这么做的。
- **为什么 `by_person` 放在模型看得见的 schema 里**：MCP 的调用只有 `name` 和 `arguments` 两个格子，
  没有第三条通道。与其藏一个未声明的字段，不如把它写清楚并说明「你不要设」。模型真设了，也只是把
  自己的动作标成人的，然后在下一次调用上读到一句「有人碰过这一页」——是一句让它困惑的话，不是一个
  安全洞。

## 4. 代价与已知缺口

- 人和模型可以同时动同一页，**冲突是可能的**：模型在 `browser_eval` 里量像素的那一瞬间，人点了一下，
  量到的就是另一帧。粒度到此为止——两边的调用在浏览器那一侧本来就是串行的，一次调用是毫秒级，
  而一轮是分钟级。用一句话换掉锁，换来的是这个。
- `by_person` 在模型看得见的 schema 里（§3 最后一条）。
- 报告轮花掉的 token 和钱不受那两个上限的二次检查（它在 `halt_reason_for` 之后、模型调用之前就定了）；
  一次不带工具的调用的量级和一次普通调用相同。
- 跨回合仍然只带用户消息与最终报告（F-44）。本 ADR 让**失败的那一轮也有报告**，所以 F-44 最疼的那一半
  （下一轮什么都不知道）缓解了，但工具结果仍然不过回合。

## 5. 证据

- `tests/runtime/test_agent_runtime.py`：步数上限买下一轮写报告（报告随 `output_text` 出来、仍然是
  `max_steps` 失败、正好花掉 `max_steps` 步、收尾请求不带工具且说明了原因）；截止时间不买（当场结束、
  一次模型调用都没有）。原有那三条「步数上限停住跑飞的一轮」原样通过——预留不改变它们的数。
- `tests/apps/test_browser_mcp_server.py`：帧带地址、已编码的地址不二次编码、没打开页面就不带地址；
  人的一次手势只报给模型一次、模型自己的输入不算人的。
- `tests/api/test_browser_input_api.py`：有回合在跑不再拒绝而是照送并报回合数（这条是上一版 409
  断言的翻案）；安静的进程报 0；403 与 503 不动。
- `web/src/features/code/BrowserFrame.test.tsx`：回合在跑时照样送进去并说一声、那句话四秒后退下去；
  画面底下写着解码后的路径。
- 门禁与实测见 `docs/status.md` 第八十七批。
