# ADR-0121：只改一个数字的循环会被拒绝；连着做同一件事的步骤折成一行

- 状态：Accepted
- 日期：2026-09-13
- 关联：ADR-0116（重复的调用按记录作答——本 ADR 补上它明说够不着的那一种循环）、ADR-0114（同一工具每 25 次一句
  提醒——本 ADR 在它失效的地方加一道拒绝）、ADR-0119（步数用尽时最后一步写报告——那一轮的报告正是这件事的证据）

## 1. 背景

用户在控制台里说「请你重新编写马里奥」，贴回来的步骤列表是：查看项目目录、读取项目目录失败、几次读取，然后
**113 行一模一样的「在本机执行命令」**，最后是报告。用户问：

> 完成一项任务会这么长的执行吗？可能有问题，二是如果就是有这么长的很影响感官，需要折叠和优化流式输出

两件事都是真的。

1. **这不是任务本来就长，是一个循环。** 事件记录（`ses_9e33…`，`run_d1ff…`）：121 次工具调用里 113 次是
   `project_run`，参数大小从第 20 次起停在 133 字节、偶尔 134、135，模型在这些步骤上一个字也没说。这一轮以
   `RunFailed: max_steps` 结束，最后一步按 ADR-0119 写了报告，报告自己说清了发生了什么：

   > 用 `project_run` 反复执行 `python3 -c` 去逐段打印 `AGENTS.md` 里 `## mario.html` 标题之前的字符……用同一个
   > 命令、只改偏移量，连续跑了 100 多次，直到撞上本轮的调用上限。

   ADR-0116 的「同一个调用按记录作答」够不着它：每一次偏移量不同，签名就不同，一次也没有被当成重复。ADR-0114
   的提醒在第 25、50、75、100 次各出现一次，模型四次都读过去了。**`mario.html` 一个字节都没写**；是下一轮
   才把它写出来的（100 步、1 次写入加 23 次编辑、`RunCompleted`）。
2. **步骤列表一步一行。** 113 行同样的动作回答不了读者任何问题——要翻过一整屏才知道它其实只做了一件事；正在
   跑的时候列表一步长一行，读者看到的是一条不停变长的清单。

### 1.1 对照 Claude Code

| | Claude Code | 本仓库（本 ADR 之前） | 本 ADR |
|---|---|---|---|
| 同一个调用连发 | 模型自己停；工具结果带 harness 的提醒 | 按记录作答，第三次收走工具（ADR-0116） | 不变 |
| 只改一个数字连发 | 同上，靠模型 | 每 25 次一句提醒（ADR-0114），可以被读过去 | 第 8 次起拒绝并说明，第 3 次拒绝收走工具，模型写报告 |
| 连着的同类工具调用 | 两段话之间收成一行摘要（「Ran N commands」），点开是逐条 | 一步一行 | 连续 ≥3 步同一动作折成「动作 ×N」，点开逐条，正在跑的那一步收着也看得见 |

## 2. 决定

### 2.1 形状：把数字抹掉之后的调用

`_call_shape(call)`：工具名加参数，参数里的每个 JSON 数字换成 `#`、**字符串里的每一串数字也换成 `#`**
（一条命令就是一个字符串，`python3 -c "print(s[40:80])"` 里没有一个 JSON 数字）。布尔值不算数字，嵌套照走。
两个调用形状相同，就是只有数字不同：偏移、长度、行号、正则量词。这正是「拿工具当尺子一格一格量」的指纹——
这一轮的 `s[40:80]`、`s[80:120]`，ADR-0114 那一轮用 `{96}`、`{89}`、`{79}` 二分一个字符串的长度。

### 2.2 同一形状的第 8 次起拒绝，第 3 次拒绝收走工具

- `_RunLedger.shape_counts` 按形状计数；在批处理里排在「按记录作答」之后（字面重复由记录作答，不重复计数）、
  「不在提供的工具里」之后（没给这个运行的工具不算进它跑不了的循环）。
- 计数超过 `MAX_SAME_SHAPE = 7`：这一次**不派发**，`invalid_tool_input` 作答，那句话写给模型——这是第几次、只有
  数字在变、一格一格量没有在得到答案；把整个迭代放进一次调用（一条命令里循环、一次打印全部），或者就用已经
  知道的去做；这个形状在别的东西改动文件之前一直会被拒绝。
- 这种拒绝超过 `MAX_SHAPE_REFUSALS = 2` 次：收走工具（`tools_withdrawn`，和 ADR-0116 同一个开关），那句话加上
  「写你的报告」。下一次请求不带工具，模型以报告结束，`RunCompleted`。
- **重置规则**：一批里派发了任何非只读调用、世界版本前进时，清掉**这一批没派发过的**形状的计数。「跑测试、
  改代码、跑测试」不是循环——中间那次编辑正是第二次运行要回答的问题，它的计数重新开始。一个形状**自己的**
  派发不重置自己：`python3 -c` 是非只读的，如果每次派发都重置，命令循环就永远看不见——和 `answered` 那条规矩
  同一个道理：一个调用自己的效果不算作它自己重复的理由。

### 2.3 7 这个数是量出来的

事件记录里不存参数（这套部署不开 `record_step_inputs`），能用的代理是「同一工具、连续、参数大小相差不超过
2 字节」的最长连串。当天本机事件记录里所有带参数大小的运行：

| 结局 | 运行数 | 最长连串中位数 | p90 | 最大 |
|---|---|---|---|---|
| `RunCompleted` | 15 | 1 | 3 | 3 |
| `RunFailed` | 5 | 2 | 66 | 109 |

7 在所有完成的运行之上留足余量，把那一轮的循环在第 7 次停住，而不是第 113 次。样本小，写在这里，数字会随
新的记录复核。

### 2.4 连着做同一件事的步骤折成一行

- `web/src/features/code/foldSteps.ts`：连续 **≥ 3** 步、**同一个动作标题**、**没有自己的思考文字**、**成败
  同一类**（成功与进行中一类，失败与被拒一类）的步骤折成一项。有思考的一步不折，并把前后分成两串——那是模型在
  那一步说的话；失败不折进成功的数字里——那是读者翻列表的首要原因；正在往外流思考的那一步不折。
- `CodeTurn.tsx` 的 `FoldRow`：收着是一行「图标 动作 ×N 最后那一步的对象 结局」，点开是逐条、和没折时一样的行。
  **有一步在跑时，那一步挂在收着的摘要底下**，命令和进度照常看得见——这是「优化流式输出」那一半：列表不再一步长
  一行，摘要上的数字在涨，正在发生的那一条始终在眼前。折叠项的 key 由第一步派生，一串正在跑的命令多一步时不
  重新挂载，读者展开过就不会被收回去。开合由这一行自己的状态管，不交给 `<details>` 的原生切换（受控的 `open`
  加原生切换会一次点击切两次）。
- **第二层：折完还长的一轮，前面收成一行。** 同一动作的折叠对「一个动作做一百遍」有效，对「很多种动作交替做」
  无效——那一轮成功重写马里奥的回合 101 次调用，折完同一动作之后在控制台上仍是 59 行（编辑、求值、打开页面、
  求值、编辑，没有哪种连着三次）。`foldHead`：第一层之后仍多于 `VISIBLE_TAIL + 2`（8）项时，只留最后 6 项，前面的
  收成一行「前面 N 步」加每种做了几次（复用 `summariseGroups`，失败的种类排在最前）。展开是原样的行，同一动作的
  折叠照样在里面。跑着的时候，留在眼前的那几行就是正在发生的事。

## 3. 为什么是这些做法

- **为什么拒绝而不是再加一句提醒**：提醒已经有了，四次都被读过去。一条不派发的拒绝没有副作用、不花那一次调用的
  时间，而且模型下一步的请求里有一个它不能忽略的事实：这个调用没有发生。
- **为什么是形状而不是「同一工具」**：同一工具的计数分不开「在一棵大树里做三十次不同的搜索」和「把一个数字加
  三十次」；ADR-0114 的提醒因此不能拒绝。形状分得开：只有数字在变，才是一格一格量。
- **为什么拒绝之后还给两次机会**：被拒绝的模型常常会转向正事（这一轮转向的正事就是写文件）；只有继续提出同一
  形状的，才说明它没有在读。
- **为什么在前端折叠而不是在运行时少发事件**：事件是事实来源（审计、事件记录、回放），少发就是少记；这是读的
  问题，在读的地方解决。
- **为什么是 3**：两行一样的动作排在一起不碍眼，折成一行反而多一次点击。

## 4. 代价与已知缺口

- **交替的循环看不见**（F-46）：形状 A、形状 B、A、B……每次非只读派发都会清掉另一个形状的计数；靠变字母而不是
  变数字来一格一格量的也不算同一形状。它们仍然只有 ADR-0114 的提醒。
- 合法地用同一形状迭代超过 7 次（例如一次读一个窗口读一份很大的文件、逐个检查 15 行关卡）会从第 8 次起被拒；
  拒绝那句话告诉它放进一次调用，这本来就是更好的做法。
- 阈值来自 20 个运行的小样本和一个代理量（参数大小），不是参数本身。
- 折叠只在 Code 页；Task 时间线与 Chat 的步骤列表另有自己的分组（`summariseGroups`），这次没动。

## 5. 证据

- `tests/runtime/test_agent_runtime.py` +4：只读循环只改数字，第 8 次起拒绝、第 10 次收走工具、运行以模型自己的话
  完成；命令循环（非只读）不被自己的派发重置；「跑测试、编辑、跑测试」十二次不算循环；形状把数字和字符串里的
  数字抹掉、其余照留。ADR-0114 那几条测试的夹具原来用 `doc_0`…`doc_25` 这种只差数字的 id，现在改成字母
  （`_lettered`），它们要模拟的是「每次一个新问题」，不能和本 ADR 要拦的循环撞在一起。
- `web/src/features/code/foldSteps.test.ts` 11 条（第一层 7、`foldHead` 4：短的不动、长的前面收起并留最后 6 项、
  一轮往下长时 key 不变、失败的种类排在摘要最前）、`CodeTurn.test.tsx` 3 条（113 步折成一行点开才逐条；跑着时收着
  的那一行底下看得见正在执行的一步；交替的 30 步是「前面 24 步」加最后 6 行）。
- 门禁与实测见 `docs/status.md` 第八十九批。
