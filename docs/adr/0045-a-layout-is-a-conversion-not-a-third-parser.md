# ADR-045：版面是一次转换，不是第三条 docx 解析路径

- 决策点：[ADR-043](./0043-docx-reading-is-a-native-tool.md) 把「读」的形状定死之后，
  控制台仍然只有一份**抽出来的文字**——`adapters/documents/docx.py:14-20` 的模块
  docstring 自己写着它「drops everything that made it a document: styles, images,
  headers, page geometry」。补「看得见的那一份」时，保真度从哪里来：
  (a) 服务端用 LibreOffice 转 PDF、交给浏览器自带阅读器画；
  (b) 前端塞一个 docx 渲染库自己画；
  (c) 不做，只把丢掉的东西数出来。
  以及：新路径会不会变成全仓第二条 docx 解析路径
- 状态：**接受**。选 (a)，并且 (c) 同批落地——两者不是替代关系，见 §6
- 日期：2026-08-12
- 影响：新增 `adapters/documents/fidelity.py`（转换器 + 内容寻址缓存）与
  `GET /v1/artifacts/{id}/pdf`；`DocumentPreview` 增加六个计数字段并接到前端。
  **零新增配置叶子、零 `config/ownership.yaml` 变动、配置 schema 保持 `1.14`、零迁移、
  零新增 Python 依赖。** 新增一个**非 Python 的外部可执行文件依赖**（LibreOffice），
  这是本项目第一次，代价写在 §4
- 依赖：[ADR-043](./0043-docx-reading-is-a-native-tool.md) §5（全仓只有一条 docx 解析
  路径：本条**遵守**，转换器复用 `preflight_docx` 而不自己开 `Document`）与 §7
  （数出表达不了的东西：本条同批落地）、
  [ADR-042](./0042-blocking-belongs-to-the-adapter.md) §6（`asyncio.to_thread` 与
  DNS 解析共用默认 executor：本条因此**不用线程**，见 §3.3）、
  [ADR-026](./0026-word-docx-is-an-mcp-artifact.md) §2.2（MCP server 不接收路径：
  本条的转换器**不是** MCP 工具，也不接收路径，见 §5）

## 1. 背景：控制台有一份读得出来的文档，没有一份看得见的文档

`GET /v1/artifacts/{id}/preview` 抽出文字与表格，按文档顺序排好，这对「这份报告写了
什么」是够的。对「这份报告长什么样」一点都不够，而后者恰恰是 Word 之所以是 Word 的
原因——本项目自己的渲染器为中文毕业论文格式设置的页边距、字号、行距、表格线，在文字
预览里**一样都不存在**。

更尖锐的是 ADR-043 §7 已经点破的那件事：`docx.py:118-121` 的 heading 识别只认内置
`Heading 1`..`Heading 9` 与 `Title`，**本项目自己加的自定义样式一律降级成普通段落**。
也就是说，最需要看版面的那一类文档（这个项目自己生成的），恰好是文字预览损失最大的
那一类。

## 2. 决策：把文档交给拥有这个格式的渲染器，然后画它的输出

`adapters/documents/fidelity.py` 把 `.docx` 交给 headless LibreOffice 转成 PDF，路由
把 PDF 原样返回，浏览器用自带的 PDF 阅读器画。前端不引入任何渲染库。

选 (a) 的理由不是「LibreOffice 好用」，是**排版 OOXML 不是一个预览能重新实现的东西**：
这个格式的参考实现就是字处理器。要么用一个，要么接受一份不像原文的图。

## 3. 被否决的方案

### 3.1 前端塞一个 docx 渲染库

否决的理由和 `docx.py:8-12` 否决客户端提取的是同一条，逐字适用第二次：

> previewing one client-side means shipping a zip reader and an XML parser to
> every page load in order to re-derive text this process can already produce

版面比文字更甚——客户端渲染要把 zip 读取器、XML 解析器**和一个排版引擎**发给每一个
访客的标签页，去重新推导这个进程转一次就能缓存住的东西。而且它会长出第二套「什么样式
认得、什么样式不认得」的判断，与服务端那套不一致时，两个面板会对同一份文档给出不同的
答案。

### 3.2 让转换器成为第三条 docx 解析路径

**没有否决，是约束。** ADR-043 §5 要求全仓只有一条 docx 解析路径，且
`preflight_docx` 的三道 zip 炸弹闸对每个调用者强制。转换器**复用** `preflight_docx`，
自己不碰 `Document(BytesIO(...))`——它把字节交给外部程序，本身不解析。所以这条路径
新增的是一个进程，不是一个解析器。

### 3.3 把转换塞进线程池

ADR-042 §6 记过：`asyncio.to_thread` 与 `loop.getaddrinfo` 共用 CPython 的默认
executor。一次转换实测约两秒（§4.1），停在默认 executor 里就是每一个其他调用者的名字
解析被拖两秒。所以转换用 `asyncio.create_subprocess_exec` 起子进程，**一个线程都不占**。

### 3.4 把 PDF 存进 ArtifactStore

否决。它是**缓存产物不是交付物**：由字节唯一决定、随时可以重算、没有独立的所有权语义。
存进去会让它出现在用户的产出列表里，看起来像一件 Task 交付的东西，而它不是。

## 4. 代价，写在正面

### 4.1 第一个非 Python 的外部依赖

`python-docx` 是主依赖，装不上会在 CI 红。LibreOffice 不是——它是一个几百 MB 的可执行
文件，**没有它的部署上这个端点必然 503**。这条不能靠「装上就行了」带过，因为它改变了
「跑起来」的含义：本项目此前只要有 Python 环境就完整，现在有一项能力取决于宿主装了
什么。

缓解写在设计里而不是写在文档里：`find_soffice()` 返回 `None` 而不是抛异常，路由把它
映射成 503 而不是 500，前端据此**安静回落到文字预览**并说明原因。没有转换器的部署不是
坏的部署，它只是少一个视图。

### 4.2 镜像会显著变大，而构建依赖外部软件源

实测（2026-08-12，`python:3.12.13-slim-bookworm`，aarch64，`--no-install-recommends`）：

| 层 | 镜像体积 | 增量 |
|---|---|---|
| 基础镜像 | 205 MB | — |
| `+ libreoffice-writer` | 759 MB | **+554 MB** |
| `+ fonts-noto-cjk` | 928 MB | **+169 MB** |

**总增量约 723 MB**，不是「装 Writer 就只多几百 MB」那么便宜——本 ADR 初稿写的 400 MB
是估的，实测比它大接近一倍，这里按实测订正。装整套 `libreoffice` 只会更大，而本项目只
转 docx，所以仍然只装 Writer。

在本项目**真实镜像**上复核，两个开关值各构建一次：

| 镜像 | 体积 | `find_soffice()` | `GET /v1/artifacts/{id}/pdf` |
|---|---|---|---|
| `WITH_FIDELITY_PREVIEW=0`（默认） | 1.24 GB | `None` | **503**，`application/json` |
| `WITH_FIDELITY_PREVIEW=1` | 1.96 GB | `/usr/bin/soffice` | **200**，`application/pdf` |

差 **720 MB**，与上表的分层测算一致。503 那一行是 §4.1 承诺的降级在真实默认镜像里的
实测结果，不是设计意图的复述。

这意味着镜像构建多一次几百 MB 的外部下载，**而这一步会失败**——本轮落地当天，本机安装
LibreOffice 的第一次尝试就因为下载断流失败（`curl: (18) transfer closed with 175317
bytes remaining`）。

因此 Dockerfile 把它做成**构建期开关，默认不装**：

```
docker build --build-arg WITH_FIDELITY_PREVIEW=1 -t agent-workbench .
```

默认构建的镜像大小不变、构建成功率不变、不新增网络依赖，代价是默认镜像上这个端点恒
503（回落路径见 §4.1）。

### 4.3 不装 CJK 字体的话中文会渲染成方块，而测试不会红

这一条写在正文而不是 Dockerfile 注释里，因为它的症状离原因极远。**2026-08-12 用一组
对照实验验证过，不是推测**——两个镜像只差 `fonts-noto-cjk` 一个包，同一份
`render_document` 产出的中文文档，在容器内用同一条命令转换：

| | CJK 字体数 | 转换退出码 | PDF 体积 | 人眼所见 |
|---|---|---|---|---|
| 装了 `fonts-noto-cjk` | 30 | **0** | 46571 B | 标题、正文、项目符号、表格**全部正确** |
| 没装 | 0 | **0** | 21253 B | **每一个汉字都是方块**，ASCII 正常 |

**两边的退出码都是 0。** 转换「成功」，产出了 PDF，进程正常退出，没有任何一条测试会红
——只有人打开那张图才看得见。这就是为什么这一条必须写在 ADR 正文里而不是 Dockerfile
的注释里：它是一个不会自己报警的失败。

结论：开启开关时 `fonts-noto-cjk` 是**承重的**，不是锦上添花。

本机 macOS 不需要额外装（系统自带 CJK 字体，实测渲染正确）。**Debian 镜像里的中文
渲染已验证**（上表），这句话此前写的是「未验证」，本次构建之后订正。

### 4.4 转换有秒级成本，必须串行

实测（本机 macOS，Apple Silicon，本项目 `render_document` 产出的中文文档）：

| 场景 | 耗时 |
|---|---|
| 安装后第一次转换（LibreOffice 建字体缓存） | 14.3 s |
| 稳态（复用 profile） | 2.0 s |
| 稳态（每次全新 profile） | 1.6 s |
| 全部流量指向死端口（验证是否依赖网络） | 2.9 s，产出**逐字节相同** |

两点结论：**超时定在 60 秒**留得下第一次那 14 秒；**内容寻址缓存是必需品不是优化**，
否则每次打开面板都要付 2 秒。并发限制到一次一个，理由不是正确性（每次转换用独立
profile，本来就不会互相踩）而是内存——soffice 是一个字处理器，小机器上并发几个就是
一次故障。

最后一行同时回答了一个会被反复问起的问题：**转换本身不依赖网络**。装的时候依赖，装完
之后不依赖。

## 5. 为什么不是 MCP 工具

ADR-026 §2.2 的规则是 MCP server 不接收路径、租户、所有者、artifact id。转换器要读
「某一份已授权的 artifact」，必然需要定位符——这正是 ADR-043 §2 判定读取器必须是 native
的同一条推理。但本条更简单：**转换器根本不是给模型用的**。它服务于控制台的一个面板，
调用者是路由，不是 agent。今天没有任何 agent 能触发一次转换，也不需要能。

## 6. 同批落地的另一半：数出丢掉的东西（ADR-043 §7）

保真视图不能取代计数，因为两者回答不同的问题，而且**保真视图有前提**（§4.1 的部署条件）。
文字预览是那条永远在的路径，它必须自己说清楚丢了什么。

`DocxPreview` 与 `DocumentPreview` 因此各增六个计数：图片、页眉、页脚、编号段落、脚注、
以及**被降级的自定义样式段落**。最后一个直接兑现 ADR-043 §7 的第二句要求——把「其余样式
一律降级成普通段落」这条表达边界写进结果，而不是留在代码注释里。

计数统计的是**整份文档**，不是被 `max_chars` 截断后走到的那一段，否则 `truncated=true`
时读者会以为文档只有这么多图。这一条有专门的测试钉住。

一处**已知的不一致，不修但写下来**：`table_count` 仍然只数遍历走到的部分，与上面六个
不同。修它就是改一个控制台已经在显示的数字，属于另一刀；`test_the_table_count_alone_
stops_where_the_text_does` 把这个接缝钉成了显式行为，将来改它那条测试会红。

一处**已知的缺口**：只数 `w:footnoteReference`（脚注），**不数尾注**。一份只用尾注的
文档 `footnote_count` 报 0，这是这份「诚实清单」里唯一的沉默处。要么加第七个字段、要么
改名，属于下一刀。

## 7. 配置影响：零

不新增配置叶子，不动 `config/ownership.yaml`，schema 仍 `1.14`，零迁移。

超时、缓存 TTL、缓存目录名都是模块级 `Final` 常量并各自注释了来由，照
`docx.py` 的 `MAX_PREVIEW_*` 的样子。**为什么不做成配置项**：它们没有一个是部署之间需要
不同的——转换要么能跑要么不能跑，而「能跑」的那台机器上这些数没有第二个合理取值。
加一个叶子就要加一份 ownership、一次 schema 变动和一次迁移，换来一个没有人会改的旋钮。

## 8. 明确不做

- **不做编辑。** 本条只读不写，ADR-043 §13「不决定编辑形状」仍然成立。
- **不做 xlsx / pptx。** 转换器的形状对它们同样成立（参考实现对 xlsx 还额外传了
  `SinglePageSheets`），但本项目今天不产出这两种，为不存在的路径写代码是负债。
- **不把 PDF 存进 ArtifactStore**（§3.4）。
- **不改既有 `/preview` 的行为。** 它多了六个字段，文字与 `truncated`、`table_count`
  逐字节不变。
- **不给默认镜像装 LibreOffice**（§4.2）。
- **不让能力表脱离开关说话。** 可以写「支持版面预览」，但同一句里必须写明它依赖构建时
  打开 `WITH_FIDELITY_PREVIEW`，默认镜像上这个端点恒 503。本 ADR 落地时
  `docs/status.md` 已按这个口径写；中文渲染那半句在 §4.3 的对照实验做完之后才从
  「未验证」改成「已验证」，不是先写上去再补证据。

## 9. 一处顺带修掉的既有故障，本刀之外

验证 §4.2 时发现**这个镜像在 main 上根本构建不出来**，与本条无关：
`web/src/features/evaluation/reports.ts:6-9` 直接 import
`evals/rag/reports/*.json` 四份报告（提交 5363d7a 引入），而 `.dockerignore:30` 把
`evals/` 整个排除出构建上下文，Dockerfile 的 web 阶段也只 `COPY web ./`。结果是
`tsc` 报四条 TS2307，`pnpm build` 退出 2，**镜像构建在 web 阶段就停住**。

没有人发现，因为 CI 不构建镜像。本轮把这四个文件从 `.dockerignore` 里放行并 `COPY` 到
web 阶段该在的相对深度，否则 §4.2 那两次构建一次也做不成。**这是一处与版面预览无关的
修复，应当单独成一刀。** 已单独提交并合并（PR #119），先于本条落地。

## 10. 什么会让这条决定重来

**出现一个可信的纯 Python 版面渲染器。** §4.1 的全部代价都来自「排版引擎必须是外部
程序」这个前提。前提没了，这条决定的成本结构整个变掉。

**镜像体积成为部署硬约束。** 今天 §4.2 的开关把这件事推给部署方选择。如果哪天默认镜像
必须瘦到装不下这个选项，那就要重新问「保真视图是不是该由一个独立的转换服务提供」——那是
一个服务边界问题，要它自己的 ADR。

**有 agent 需要看版面。** 本条 §5 断言转换器不是给模型用的。如果哪天一个 agent 要「看」
自己刚写的文档（把 PDF 光栅化成图片再读，正是参考实现自检时做的事），定位符和授权的
问题就全部回来了，ADR-043 §2 的推理要重新走一遍。
