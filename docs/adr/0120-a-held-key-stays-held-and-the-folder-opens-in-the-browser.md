# ADR-0120：按住的键在页面里一直按着；文件夹里的网页可以在浏览器里打开

- 状态：Accepted
- 日期：2026-09-13
- 关联：ADR-0117（人可以操作浏览器——§2.1「只转发 `browser_interact`、不转发 `browser_open`」被本 ADR
  **收窄地**翻案：人可以打开**自己项目里的文件**，仍然不能给地址）、ADR-0119（两个操作者、告知而不是锁——
  本 ADR 沿用同一套告知，并把「有人打开了另一页」加进去）、ADR-0115 §3.3（浏览器容器把项目文件夹挂在
  和 API 同一个路径上——本 ADR 的地址正是靠这一条对得上）

## 1. 背景

第八十七批合入、栈用最新代码重建之后，用户说：

> 浏览器要和文件夹里的文件进行互通，比如文件夹中的html文件可以点击预览在浏览器中，但是项目完成后，
> 人还是无法控制在浏览器中的项目预览

两件事，查实如下。

1. **「人还是无法控制」——是控制本身坏了，不是没权限。** ADR-0119 之后人的输入随时送得进去（第八十七批
   实测：回合跑着时 `POST /v1/browser/input` 200，模型报告里写着「a person operated this page directly —
   40 actions」）。但项目里的 `mario.html` 是这样读键盘的：

   ```js
   window.addEventListener("keydown", (e) => { ... this.keys.right = true; ... });
   window.addEventListener("keyup",   (e) => { ... this.keys.right = false; ... });
   // 游戏循环里，每一帧：
   if (this.keys.right && !this.keys.left) { ... }
   ```

   面板把每个键送成 `{"kind": "key"}`，浏览器那一侧是 `page.keyboard.press()`——**按下和抬起一口气做完**。
   两者之间没有一帧跑过，`keys.right` 为真的时间是零帧，**马里奥一步也不走**。按住方向键只是一串零长度的
   轻点；面板在上一次没回来时还会**丢掉**新的输入。之前的实测里「按 → 开始游戏」生效，是因为那个监听器
   在 keydown 上只做一次性的事；走、跳都要「按着」。任何读键状态的页面（几乎所有网页游戏、按住拖动的
   滑块、画布）都是同一种坏法。
2. **「文件夹中的html文件可以点击预览在浏览器中」——两张标签互不相识。** 右栏「文件夹」里点开一个
   `.html`，它在沙箱 iframe 里预览；「浏览器」那一张只能显示**模型**打开过的页面。ADR-0117 §2.1 明确不转发
   `browser_open`（「人不替模型决定它在看哪一页」）。于是一轮结束之后、或者栈重启把浏览器清空之后，
   这一张要么是别的页面、要么是「还没打开过页面」，人没有任何办法把自己项目里的网页放进去操作。
3. 顺带：焦点下 250 ms 一帧（ADR-0117）。看一次点击的结果够，**操作**不够——按住方向键走一段，每秒只看见
   四个位置。

### 1.1 对照 Claude Code

| | Claude Code desktop 的 Browser 面板 | 本仓库（本 ADR 之前） | 本 ADR |
|---|---|---|---|
| 人按住一个键 | 真浏览器，keydown…keyup 原生 | 一次 `press`，零帧 | `key_down` / `key_up` 两半，按住就是按住 |
| 输入顺序 | 原生事件队列 | 上一次没回来就丢 | 排队按序送，拖动时只保留最新的移动 |
| 打开本地文件 | 文件树 / 预览里直接在面板打开 | 只有模型能开 | 右栏 `.html` 有「在浏览器中打开」，只能开项目里的文件 |
| 从页面回到文件 | 标签页有地址 | 画面底下只有一行路径（ADR-0119） | 路径落在项目里时有「在文件夹中打开」 |
| 画面刷新 | 原生渲染 | 焦点下 4 帧/秒 | 焦点下 10 帧/秒，不叠加请求 |

## 2. 决定

### 2.1 按下和抬起是两个动作

- **浏览器端**（`apps/browser_mcp/contract.py`、`session.py`）：`browser_interact` 多五种动作——
  `key_down` / `key_up`（要 `text`，Playwright `keyboard.down` / `keyboard.up`）、`mouse_down` / `mouse_up` /
  `mouse_move`（要 `x`、`y`，先 `mouse.move` 到点上再按下或抬起——Playwright 的鼠标在指针当前位置按下）。
  `key` 仍然是轻点。工具描述对模型也说清：要「按住」就 `key_down`，等一会儿（一个会等待的
  `browser_eval`），再 `key_up`——模型验证游戏也需要它。
- **控制面**（`routes/browser_input.py`）：`KeyAction.kind` 加 `key_down` / `key_up`；新 `PointerAction`
  （`mouse_down` / `mouse_up` / `mouse_move` + 点）。
- **面板**（`BrowserFrame.tsx`）：
  - keydown 送 `key_down`，**按住期间的重复（`event.repeat`）不送**；keyup 送 `key_up`（不看修饰键——按住
    方向键时按了一下 Ctrl，抬起照样要送到）。
  - mousedown 送 `mouse_down`，按着时 mousemove 送 `mouse_move`（**合并**：排着的移动只保留最新位置），
    mouseup 送 `mouse_up`；拖出画面在离开处松开。原来的 `onClick` 去掉——按下加松开在页面里就是一次点击，
    浏览器自己合成 `click`。图片 `draggable={false}`，免得按住拖动变成把 JPEG 拖走。
  - **输入排队按序送**，一个回来了才送下一个；原来「上一次没回来就丢」对轻点无所谓，对抬起是灾难：丢掉的
    若是 `key_up`，那个键在浏览器里就一直按着。
  - **失去焦点或卸载时把还按着的全部松开**：抬起那一下发生在这块面之外，它听不到。
  - 焦点下取帧从 250 ms 改成 100 ms；取帧改成**上一张回来之后才排下一张**（`setTimeout` 链而不是
    `setInterval`），间隔一短，慢的那一次不会和下一次叠在一起。

### 2.2 文件夹里的网页可以在浏览器里打开，只能是项目里的文件

- **控制面**：`POST /v1/browser/open`，请求体**只有** `project_id` 和 `path`（`extra="forbid"`，没有 `url`
  字段——人拿到的是「打开这个我在文件夹里看得见的文件」，不是地址栏）。拒绝：没有 `mcp:browser` 403、
  浏览器不在 503、项目不是这个身份的 404（`projects.open_files` 先读项目行）、路径越出项目 400、文件不在
  404、浏览器打开失败 502。成功回 `title` 和 `turns_in_flight`。
- **地址在服务端拼，且只拼在一个地方**：`adapters/tools/browser.py` 抽出 `project_file_url(store, path)`——
  先 `store.exists(path)`（沙箱的词法与物理检查都在里面），再 `working_directory / path` 转 `file://`。
  `ProjectFileStore.working_directory` 的文档写着「它永远不是拿来拼路径的基底」，这三行只有排在 `exists`
  之后才安全；模型的 `browser_open`（`open_within_project`）和人的这条路由**用同一个函数**，而不是各写
  一份。浏览器容器把项目文件夹只读挂在和 API 同一个 `/projects` 路径上（ADR-0115 §3.3），所以这个地址
  在那一侧指的是同一个文件。
- **打开这件事走 `BrowserSlot.open_for_person(url)`**，调 `browser_open` 并带 `by_person: true`（schema 里
  同样加了这个字段，说明「你不要设」）。浏览器会话记下「有人打开了 X」，**下一次模型的浏览器调用**结果
  末尾多一句：有人从控制台打开了 X，你之前在看的那一页已经不是当前页了——和 ADR-0119 的「有人操作过」
  同一条通道、读一次就清，两件事同时发生时两句都说。
- **面板**：右栏打开的项目文件是 `.html` / `.htm` 时，页眉多「在浏览器中打开」，成功后跳到「浏览器」那一张。
  反方向：浏览器画面底下那行路径落在这段会话的项目目录**之下**时，旁边有「在文件夹中打开」——去它所在
  那一层列一次、用列出来的那一行打开，和在树里点开它走同一条路（预览要那一行的字节数）。只认目录之下
  （`/projects/demo2` 不算 `/projects/demo` 的）。「还没打开过页面」那句话也改成告诉人可以从文件夹里放一个
  进来。

## 3. 为什么是这些做法

- **为什么是两半而不是「按住多久」**：人按住多久是人决定的，面板只知道按下和抬起两个时刻；把它们原样
  送过去是唯一不猜的做法。给 `key` 加一个 `hold_ms` 参数，面板就得在按下时猜抬起。
- **为什么排队而不是丢**：丢掉的代价不对称——丢一个按下是少走一步，丢一个抬起是一直走。排队的代价是延迟，
  而延迟有上限（一次往返几十毫秒）。
- **为什么打开只给项目文件**：人要的是「把我这个网页放进去玩」，这件事项目 id + 相对路径就说完了。一个
  任意地址的入口是另一件事：它让人决定这个受控浏览器去哪儿，而这个浏览器的出网守卫、它的会话、它和模型
  共用——那是一条自己的 ADR。
- **为什么不直接让「文件夹」里点 `.html` 就开进浏览器**：沙箱 iframe 预览是读者**自己的**浏览器，零延迟、
  原生键盘，玩一局它更好；「浏览器」那一张是**模型的**浏览器，它的价值是和模型看的是同一页。两样都留，
  由人选。
- **为什么 100 ms**：看得见自己在控制的下限；一帧是回环上几十 KB 的 JPEG，本地部署付得起。推流仍然是
  另一条 ADR（F-43）。

## 4. 代价与已知缺口

- **仍然是截图轮询**（F-43）：10 帧/秒能走、能跳、能看清停在哪，打不了要求反应的动作游戏。
- 每个按下、抬起都是一次 HTTP 往返加一次 MCP 调用（本机几十毫秒）；手快的连按会排队，而不是并发。
- 按住期间按了 Shift 让 `key` 从 `a` 变成 `A` 的那种情形，抬起时名字对不上不会送；失去焦点时 `releaseHeld`
  兜底。
- 人打开页面会替换模型正在看的页面；模型在下一次浏览器调用上被告知，不会被阻止（ADR-0119 的取舍）。
- `by_person` 在 `browser_open` 的 schema 里对模型可见，理由同 ADR-0119 §3。

## 5. 证据

- `tests/apps/test_browser_mcp_server.py` +6：一个键可以作为两个动作按住、缺 `text` / 缺点的半个动作被拒
  （四种）、鼠标按下/移动/松开带着点、人打开的页面只报给模型一次、模型自己打开的不算人的。
- `tests/api/test_browser_input_api.py` +8：两半按顺序转发、缺点的鼠标动作 422；打开项目文件拼出浏览器那一侧
  的 `file://` 地址（含百分号编码的中文路径）、带 `url` 字段 422、越出项目 400、文件不在 404、别人的项目 404、
  没有 scope 403 / 没有浏览器 503。
- `tests/architecture/test_browser_forward_is_read_only.py` +1：打开请求的字段正好是 `{project_id, path}` 且
  `extra="forbid"`。
- `web/src/features/code/BrowserFrame.test.tsx`：按下再松开是 `mouse_down` + `mouse_up`；按住方向键只送一次
  按下、重复不送、松开送抬起、Ctrl 组合不送；上一次没回来时的按键按序送到；失去焦点把键和鼠标都松开；
  回合在跑时照送并说一声；路径落在项目里时「在文件夹中打开」给出相对路径；`relativeToProject` 不认前缀
  相同的另一个目录。`CodePage.test.tsx` +2：`.html` 有「在浏览器中打开」且点了跳到浏览器那一张；`.txt` 没有。
- 门禁与实测见 `docs/status.md` 第八十八批。
